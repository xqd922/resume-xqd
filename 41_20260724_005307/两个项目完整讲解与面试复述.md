## 3. 30 秒、1 分钟和 3 分钟讲法

### 3.1 30 秒版本

> 我做了一个基于 STM32F407ZE 的四足机器狗。四条腿共 8 个舵机，我通过 I2C 控制 PCA9685 扩展 PWM 通道；软件根据足端目标坐标做二维二连杆逆运动学，求出髋关节和膝关节角度，再进行限幅和 1° 步进插值。MPU6050 用于倾倒判断，另外接入了蓝牙网页控制、ESP32 语音指令和 WS2812 状态灯。

### 3.2 1 分钟版本

> 这个项目的目标是让四足机器人完成站立、前进、后退和转向等 9 种动作与姿态。系统以 STM32F407ZE 为主控，每条腿有两个关节，一共驱动 8 个舵机。因为需要多路 PWM，我通过 I2C 配置 PCA9685，把目标关节角映射为对应舵机脉宽。  
> 控制算法上，我把每条腿简化为二维二连杆模型，输入足端目标坐标，先判断目标是否在连杆可达范围，再通过余弦定理和 atan2 求两个关节角，之后做机械角度限幅和舵机零位映射。为了避免角度指令一次跳变，我使用 1° 步进插值让关节逐步到达目标。  
> 感知方面读取 MPU6050 三轴加速度和三轴角速度完成倾倒判断；交互方面通过蓝牙网页端、ESP32 语音指令控制动作，并由 WS2812 显示运行状态。

### 3.3 3 分钟版本

> 我按硬件、运动算法和交互三个部分介绍。  
> 第一是硬件。主控是 STM32F407ZE，四条腿每条腿两个舵机，共 8 路。STM32 通过 I2C 控制 PCA9685，PCA9685 把一个 PWM 周期分成 4096 个计数位置，再根据目标脉宽配置每路输出。舵机使用独立的【待本人填写】电源，并与主控共地。MPU6050 也通过 I2C 接入，用于读取三轴加速度和三轴角速度。ESP32 通过 UART4 与 STM32 通信，蓝牙控制链路使用 USART2，WS2812 负责状态显示。  
> 第二是运动控制。每条腿被简化为大腿、小腿两根连杆。上层动作生成足端目标点 $(x,y)$，逆运动学模块先检查距离是否满足 $|L_1-L_2|\le r\le L_1+L_2$，再求膝关节和髋关节角。数学角度不能直接发给舵机，还要结合每个舵机的安装方向、机械零位和安全范围进行转换。我的实现加入 0°到180°限幅，并使用 1°步进插值，降低目标角度突变产生的冲击。  
> 第三是感知和交互。MPU6050 实际输出的是六轴惯性数据，不是已经算好的姿态。我项目中使用【待本人填写真实算法】进行倾倒判断。网页端通过【待本人填写真实链路】下发动作指令；ESP32 侧通过【待本人填写语音架构】产生语音控制命令，再经 UART4 发给 STM32。  
> 项目中最难的问题是【待本人填写】。现象是【待本人填写】，我通过【示波器/逻辑分析仪/日志/断点】定位到【根因】，最终通过【修复】解决，并用【真实测试】验证。

## 5. 为什么选择 STM32F407ZE

【原理必须会】

核心特征：

- Cortex-M4F；
- 最高 168 MHz；
- 带单精度 FPU；
- 外设和定时器资源较丰富；
- 多路 UART/I2C；
- 适合同时处理运动计算和多模块通信。

面试回答：

> F407 的 M4F 和较高主频能为浮点逆运动学、多路通信和后续扩展提供余量。但二维逆运动学本身并不一定必须使用 168 MHz，选择 F407 也与现有开发板和外设资源有关。我不会简单说“频率越高越好”。

可能追问：F103 能不能实现？

> 对 8 路舵机和低频二维逆解来说，经过合理设计，F103 也可能实现。F407 的优势主要是性能、FPU、存储和接口余量，不代表 F103 完全做不了。

## 6. PCA9685 与舵机控制

### 6.1 为什么使用 PCA9685

【简历已确认】

- I2C 接口；
- 16 路 PWM；
- 每周期 12 位，即 4096 个计数位置；
- 项目使用其中 8 路驱动 8 个舵机。

回答：

> 使用 PCA9685 可以用一条 I2C 总线扩展多路 PWM，减少 STM32 定时器通道和 GPIO 占用。代价是增加外部器件、I2C 更新延迟以及内部振荡器误差。

- 目标 50 Hz；

### 6.4 角度映射

~~~c
typedef struct {
    float min_degree;
    float max_degree;
    uint16_t min_count;
    uint16_t max_count;
    float zero_offset;
    bool reversed;
} ServoCalibration;

float clamp_float(float value, float low, float high)
{
    if (value < low) return low;
    if (value > high) return high;
    return value;
}

uint16_t servo_angle_to_count(float joint_degree,
                              const ServoCalibration *cal)
{
    float degree = joint_degree + cal->zero_offset;

    if (cal->reversed) {
        degree = cal->max_degree -
                 (degree - cal->min_degree);
    }

    degree = clamp_float(degree,
                         cal->min_degree,
                         cal->max_degree);

    float ratio = (degree - cal->min_degree) /
                  (cal->max_degree - cal->min_degree);

    return (uint16_t)(cal->min_count +
           ratio * (cal->max_count - cal->min_count) +
           0.5f);
}
~~~

- 为什么每个舵机需要单独零位；

- 为什么数学角度不能直接当舵机角度；
- 为什么既要数学可达性，又要机械限位。

## 7. 二维二连杆逆运动学

### 7.1 为什么需要逆运动学

正运动学：

~~~text
已知关节角 → 求足端位置
~~~

逆运动学：

~~~text
已知足端目标位置 → 求关节角
~~~

机器狗上层更容易描述“脚要移动到哪里”，所以使用逆运动学求各关节角。

### 7.2 坐标系

必须自己画图并填写：

~~~text
髋关节原点 O
X 轴正方向：【待本人填写】
Y 轴正方向：【待本人填写】
大腿长度 L1：【待本人填写】
小腿长度 L2：【待本人填写】
角度正方向：【待本人填写】
~~~

没有统一坐标系，公式中的正负号无法讲清。

### 7.3 可达性

目标距离：

$$
r=\sqrt{x^2+y^2}
$$

可达条件：

$$
|L_1-L_2|\le r\le L_1+L_2
$$

解释：

- 超过 $L_1+L_2$：两根腿完全伸直也够不到；
- 小于 $|L_1-L_2|$：目标落入内部不可达区域。

### 7.4 膝关节角

一种角度定义下：

$$
\cos\theta_2=
\frac{x^2+y^2-L_1^2-L_2^2}{2L_1L_2}
$$

$$
\theta_2=\arccos(\cos\theta_2)
$$

浮点保护：

~~~c
cos_theta2 = clamp_float(cos_theta2, -1.0f, 1.0f);
~~~

原因：

> 浮点误差可能把理论上的 1.0 计算成 1.0000001，直接 acos 会得到 NaN。

### 7.5 髋关节角

$$
\theta_1=
atan2(y,x)-
atan2(L_2\sin\theta_2,
      L_1+L_2\cos\theta_2)
$$

### 7.6 两支解

二连杆通常存在：

- 膝盖向前；
- 膝盖向后。

数学上可通过 $\sin\theta_2$ 正负选择不同分支。机械结构通常只允许一支。

回答：

> 我的机械结构使用【待本人填写】分支。选择后还要通过舵机安装方向和零位转换到实际角度。

### 7.7 完整逆解伪代码

~~~c
typedef struct {
    float hip_rad;
    float knee_rad;
} LegAngles;

bool leg_inverse_kinematics(float x, float y,
                            float l1, float l2,
                            LegAngles *result)
{
    if (result == NULL || l1 <= 0.0f || l2 <= 0.0f) {
        return false;
    }

    float r2 = x * x + y * y;
    float r = sqrtf(r2);

    if (r > l1 + l2 || r < fabsf(l1 - l2)) {
        return false;
    }

    float cos_knee =
        (r2 - l1 * l1 - l2 * l2) /
        (2.0f * l1 * l2);

    cos_knee = clamp_float(cos_knee, -1.0f, 1.0f);

    float knee = acosf(cos_knee);
    float hip = atan2f(y, x) -
                atan2f(l2 * sinf(knee),
                       l1 + l2 * cosf(knee));

    result->hip_rad = hip;
    result->knee_rad = knee;
    return true;
}
~~~

## 8. 插值和平滑控制

### 8.1 项目实际口径

安全表达：

### 8.2 基础实现

~~~c
float move_toward(float current,
                  float target,
                  float max_step)
{
    float error = target - current;

    if (error > max_step) {
        return current + max_step;
    }
    if (error < -max_step) {
        return current - max_step;
    }
    return target;
}
~~~

每【待本人填写】ms 调用一次：

~~~c

    move_toward(current_angle, target_angle, 1.0f);
~~~

## 15. 机器狗面试追问与参考答法

### 15.1 基础层

**问：为什么使用 PCA9685？**

> 为了通过一条 I2C 总线扩展多路 PWM，降低 MCU 定时器通道和引脚占用。它提供 16 路 12 位 PWM，我使用 8 路驱动 8 个舵机。

**问：12 位是否代表舵机有 4096 个准确角度？**

> 不是。12 位只是 PWM 周期的计数分辨率，舵机实际角度分辨率还受脉宽范围、内部死区、齿轮间隙和机械结构影响。

**问：I2C 为什么需要上拉？**

> SDA/SCL 通常是开漏，只能主动拉低，释放后由上拉电阻变高，便于多设备共享和仲裁。

### 15.2 算法层

**问：逆运动学为什么有两支解？**

> 二连杆到达同一足端点时，膝关节可能向两个方向弯曲，对应 sin(theta2) 的正负。机械结构通常只允许其中一支。

**问：为什么使用 atan2 而不是 atan？**

> atan2 同时使用 x、y 的符号，能区分象限，并能更好处理 x 接近 0 的情况。

**问：为什么先做可达性判断？**

> 不可达目标会让余弦公式超出 [-1,1]，同时在机械上也无法实现。提前判断能避免 NaN 和危险角度。

### 15.3 控制层

**问：1° 插值有什么问题？**

> 它能限制每次角度变化，但速度取决于调用周期，起停速度仍不连续，不同关节也可能不同步。更完善的是时间参数化轨迹。

**问：为什么还会抖？**

> 供电压降、舵机死区、机械间隙、PWM 频率误差、目标更新周期和零位标定都可能引起抖动。

**问：普通舵机是不是闭环？**

> 舵机内部通常有位置闭环，但 STM32 未必能读取真实关节角，所以从整机控制角度看仍缺少外部关节和足端反馈。

### 15.4 感知层

**问：MPU6050 六轴是什么？**

> 三轴加速度和三轴角速度，不是六个姿态角。

**问：为什么航向角会漂？**

> 六轴 IMU 没有绝对航向参考，陀螺仪零偏积分会累积，通常需要磁力计或外部参考校正。

### 15.5 压力层

**问：项目是不是只是调用现成库？**

回答模板：

> 我复用了【真实库/驱动】，自己完成的是【真实模块】。我能说明接口、数据流、逆解公式、舵机映射和调试过程。没有自己完成的部分我不会算到个人产出。

**问：为什么没有闭环平衡？**

> 当前项目定位是二维逆解和预设动作控制，MPU6050用于倾倒检测，没有实现关节反馈、足端力反馈或完整动态平衡。这是项目边界，也是下一步升级方向。

**问：如果重做，优先改什么？**

> 第一是电源和安全监测；第二是固定周期轨迹规划；第三是增加关节或足端反馈；第四是通信看门狗和系统化测试。

### 22.2 ADC 换算

- 传感器误差；

- 采样时间；
- PCB。

### 22.3 采样时间

### 22.4 滑动平均

若实际使用：

~~~c
#define WINDOW_SIZE 8U

typedef struct {
    uint16_t data[WINDOW_SIZE];
    uint32_t sum;
    uint8_t index;
    uint8_t count;
} MovingAverage;

uint16_t moving_average_update(MovingAverage *filter,
                               uint16_t sample)
{
    filter->sum -= filter->data[filter->index];
    filter->data[filter->index] = sample;
    filter->sum += sample;

    filter->index =
        (uint8_t)((filter->index + 1U) % WINDOW_SIZE);

    if (filter->count < WINDOW_SIZE) {
        ++filter->count;
    }

    return (uint16_t)(filter->sum / filter->count);
}
~~~

使用前结构必须清零。

若实际没用：

> 项目直接使用【真实方法】，滑动平均是我复盘后准备增加的优化。

## 24. HC-SR04 超声波测距

### 24.1 原理

1. Trig 输出至少约 10 μs 高脉冲；
2. 模块发射超声波；
3. Echo 高电平表示等待回波；
4. 记录 Echo 高电平时间；
5. 根据声波往返时间计算距离。

$$
Distance=\frac{Time\times SpeedOfSound}{2}
$$

室温附近常用近似：

$$
Distance_{cm}\approx Time_{\mu s}/58
$$

### 24.2 为什么除以 2

测到的是发射到目标、再反射回来的往返路程。

### 24.3 输入捕获

推荐流程：

~~~text
等待上升沿
→ 记录 start
→ 切换下降沿
→ 记录 end
→ 处理溢出
→ 计算脉宽
→ 标记数据有效
~~~

~~~c
typedef enum {
    WAIT_ECHO_RISING,
    WAIT_ECHO_FALLING
} EchoState;
~~~

实际实现：

> 我使用【输入捕获/外部中断/轮询】测量 Echo。

### 24.4 超时

没有回波时不能永久等待：

~~~c
if ((uint32_t)(now_us - trigger_us) >
    ECHO_TIMEOUT_US) {
    distance_valid = false;
    echo_state = WAIT_ECHO_RISING;
}
~~~

### 24.5 5 V Echo

常见 HC-SR04 使用 5 V，Echo 可能接近 5 V。

回答：

> 我检查 STM32 对应引脚是否 5 V tolerant 及其工作模式；更稳妥的方法是电阻分压或电平转换。

真实电路：

> 我的 Echo 【直接连接/分压/电平转换】，具体参数是【待本人填写】。

### 24.6 误差

- 温度影响声速；
- 太近/太远；
- 软物体；
- 斜面；
- 多次回波；
- 多模块串扰；
- 定时器分辨率；
- 异常 0 值。

可使用中值滤波去除偶发毛刺。

I2C 400 kbit/s 传 1024 字节，净数据至少约 20.5 ms，加 ACK、地址和命令后更久。

因此：

- 不必每次主循环全屏刷新；
- 内容变化时刷新；
- 可降低 UI 频率；
- 显示故障不应拖死灯的核心控制；
- I2C 操作应有超时。

## 32. 台灯面试追问与参考答法

### 32.1 硬件层

**问：为什么不能直接用 GPIO 驱动灯？**

> GPIO 电流能力有限，大功率负载需要 MOSFET 或专用驱动，同时考虑电源、功耗和保护。

**问：去耦电容有什么用？**

> 为 MCU 开关瞬态提供局部高频电流，降低电源波动。位置和回流路径与容值同样重要。

**问：第一次上电怎么做？**

> 先检查短路和方向，用限流电源验证电源轨，再确认复位、SWD、最小程序，之后逐个模块接入，最后接功率负载。

### 32.2 ADC/PWM 层

**问：12 位 ADC 是不是精度就是 1/4096？**

> 1/4096 是理想量化分辨率，实际精度还受 Vref、噪声、偏置、增益、源阻抗和 PCB 等影响。

**问：为什么光阈值会抖？**

> 传感器噪声和环境光波动会让 ADC 在阈值附近反复穿越，可通过滤波、迟滞和最短保持时间解决。

**问：PWM 频率怎么计算？**

> 先确认真正的 TIM2 输入时钟，再使用 $f=f_{TIM}/((PSC+1)(ARR+1))$，占空比近似为 CCR/(ARR+1)。

### 32.3 传感器层

**问：HC-SR04 为什么除以 2？**

> Echo 时间对应声波往返路程。

**问：没有回波怎么办？**

> 设置超时，标记数据无效，恢复捕获状态，不能永久阻塞。

**问：PIR 能判断静止的人吗？**

> PIR 更擅长检测热辐射变化，静止人员可能不持续触发，所以需要保持时间或其他传感器辅助。

### 32.4 软件层

**问：四模式冲突怎么办？**

> 我定义【真实优先级】，安全故障首先处理，当前模式决定谁拥有控制权；蓝牙断开或命令超时后回到【真实状态】。

**问：OLED 为什么不每圈刷新？**

> 全屏数据量较大，会占用 I2C 和 CPU。显示不是实时控制关键路径，可按较低周期或内容变化刷新。

### 32.5 压力层

**问：你说传感器融合，算法在哪里？**

> 我的融合是规则级决策：光敏负责明暗，红外负责人员活动，超声波负责距离；按【真实规则】组合，并处理数据有效性。没有实现卡尔曼等数学融合，不会这样声称。

**问：这算闭环吗？**

> 更准确是感知、决策、执行和显示的完整链路。只有持续测量受控输出并按目标调节，才是严格的反馈闭环。

**问：PCB 真的是你独立做的吗？**

> 我独立完成【真实范围】，复用或参考了【真实部分】。我能在图上指出电源、最小系统、去耦、接口和调试问题；没有做的部分不算个人产出。

**问：如果重做先改什么？**

> 第一是明确模式状态机和异常回退；第二是 ADC 滤波与迟滞；第三是超声波超时和数据有效性；第四是电源、接口保护和系统化测试。

## 42. 最后速记

### 机器狗五句话

1. F407 是运动主控，PCA9685 扩展 8 路舵机 PWM。
2. 足端坐标经过二维二连杆逆解得到两个关节角。
3. 可达性、分支、机械限位和舵机标定缺一不可。
4. 1° 插值降低角度阶跃冲击，但不是完整轨迹规划。
5. MPU6050 输出六轴惯性数据，蓝牙/ESP32提供控制输入。

### 台灯五句话

1. F103 控制自绘 PCB 上的传感器、灯、显示和串口模块。
2. 光敏分压经 ADC 采样，TIM2 PWM 调节亮度。
3. 红外负责人员信息，HC-SR04负责距离，规则级组合做自动控制。
4. 自动、手动、蓝牙、语音四模式必须定义优先级和回退。
5. 超声波要超时，Echo 要关注 5 V，显示不能阻塞核心控制。
