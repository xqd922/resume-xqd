## 0. 这份文档怎么用

这不是一份“背答案合集”，而是一套从简历事实到技术原理、再到面试表达的训练手册。

每个知识点按五层学习：

1. **一句话**：15 秒内说清它是什么。
2. **通俗原理**：不用术语堆砌，也能讲明白为什么。
3. **简历落点**：它在机器狗、台灯或实习里具体做什么。
4. **代码 / 计算 / 波形**：能举出一个可验证的例子。
5. **连续追问**：至少扛住面试官三层“为什么”。

建议的练习方法：

- 第一遍：通读并标记所有不懂的词。
- 第二遍：手写关键公式、通信时序和项目框图。
- 第三遍：关闭文档，对着手机录音回答。
- 第四遍：随机抽题，限定 30 秒组织答案。
- 第五遍：让别人故意打断并追问，训练恢复能力。

合格标准不是逐字背诵，而是：

- 同一个问题换一种问法仍能回答；
- 能用自己的项目举例；
- 能画出数据流和控制流；
- 不知道时能说清边界，不胡编。

## 2. 简历中三处必须用更严谨的口径

### 2.1 “9 类步态动作”

站立通常不是“步态”。前进、后退、转向中也可能使用同一种步态，只是轨迹或相位不同。

更安全的面试说法：

> 我实现了站立、前进、后退、左右转向等共 9 种动作和姿态。其中连续行走部分通过四条腿的相位差形成步态，站立属于静态姿态，不把它严格称为步态。

### 2.2 “1° 插值消除机械冲击与抖动”

插值能减小指令突变造成的冲击，但不能保证消除抖动。抖动还可能来自供电压降、舵机死区、机械间隙、控制周期抖动、角度映射误差等。

更安全的面试说法：

> 我把目标角度分解为 1° 的小步，并按固定控制周期更新，从而减小角度阶跃带来的机械冲击。实际效果是运动更平滑；“完全消除抖动”不严谨，供电和机械间隙仍会影响稳定性。

### 2.3 “MPU6050 读取六轴姿态”

MPU6050 直接输出的是三轴加速度和三轴角速度，即六轴惯性数据，不是已经算好的稳定姿态角。姿态角需要计算或融合。

更安全的面试说法：

> MPU6050 提供三轴加速度和三轴角速度。我先读取并做零偏校准，再根据加速度估算静态倾角；如果需要连续姿态，就用互补滤波把加速度的长期稳定性与陀螺仪的短期响应结合。项目中据此做倾倒阈值判断和状态反馈。

如果你实际没有做互补滤波，就不能说做过。应改成：

> 项目只读取六轴原始数据，并基于加速度方向做倾倒判断，没有实现完整姿态融合。

## 4. 嵌入式总基础：先建立一张完整地图

### 4.1 什么是嵌入式系统

**一句话回答：**

> 嵌入式系统是为特定功能设计、软硬件结合、通常受成本、功耗、内存和实时性约束的计算系统。

机器狗和台灯都属于嵌入式系统：

- 输入：传感器、按键、通信指令；
- 处理：STM32 中的 C/C++ 程序；
- 输出：舵机、灯、OLED、报警；
- 约束：供电、电流、实时响应、Flash/RAM、机械安全。

### 4.2 MCU、CPU、SoC、开发板的区别

| 名称 | 通俗解释 | 简历例子 |
|---|---|---|
| CPU | 执行指令的核心 | Cortex-M3、Cortex-M4 |
| MCU | CPU、Flash、RAM、外设集成在一颗芯片中 | STM32F103C8T6、STM32F407ZE |
| SoC | 集成度更高，常含无线、复杂外设甚至多核 | ESP32 可视为无线 SoC / MCU |
| 开发板 | 把芯片、电源、下载口、晶振、接口做成可用板卡 | 你实际使用的 [待填写] 板 |

### 4.3 二进制、十六进制与位操作

寄存器按位控制，所以嵌入式必须熟练：

- 1 字节 = 8 bit；
- 0x20 = 二进制 0010 0000；
- 设置某位：寄存器 OR 掩码；
- 清除某位：寄存器 AND 取反掩码；
- 翻转某位：寄存器 XOR 掩码；
- 读取某位：寄存器 AND 掩码后判断。

~~~c
#define BIT(n) (1UL << (n))

reg |= BIT(5);          // 置位 bit5
reg &= ~BIT(5);         // 清零 bit5
reg ^= BIT(5);          // 翻转 bit5
bool is_set = (reg & BIT(5)) != 0U;
~~~

面试题：为什么掩码常写 1UL 而不是 1？

参考答案：

> 1UL 明确使用无符号长整型，左移时类型和位宽更清楚，也能减少移到高位时的有符号问题。不过最终还应匹配寄存器实际使用的 uint32_t。

### 4.4 大端、小端

多字节数据在内存中的字节顺序：

- 小端：低有效字节放低地址；Cortex-M 常用小端。
- 大端：高有效字节放低地址。

~~~c
uint16_t value = 0x1234;
// 小端内存：低地址 0x34，高地址 0x12
~~~

通信协议的字节序由协议规定，不能直接假设与 MCU 内存相同。发包时应显式拆字节。

~~~c
buf[0] = (uint8_t)(value >> 8);   // 网络协议若规定高字节在前
buf[1] = (uint8_t)(value & 0xFFU);
~~~

### 4.5 存储映射与寄存器

**一句话回答：**

> STM32 把 Flash、RAM 和外设寄存器映射到统一地址空间，CPU 通过读写特定地址控制硬件，这叫内存映射 I/O。

寄存器通常用 volatile 修饰，因为：

- 硬件可能自行改变值；
- 中断可能异步改变值；
- 编译器不能把每次访问优化掉。

volatile 不等于：

- 原子操作；
- 线程安全；
- 内存屏障；
- “变量一定放进 RAM”。

### 4.6 从上电到 main

典型流程：

1. 复位后从向量表取得初始栈顶地址；
2. 进入 Reset_Handler；
3. 设置时钟和底层环境；
4. 把 Flash 中的已初始化数据复制到 RAM 的 .data；
5. 把 .bss 清零；
6. 初始化 C/C++ 运行时；
7. 调用 main；
8. main 一般进入永久循环或启动 RTOS 调度器。

常见内存区域：

| 区域 | 放什么 | 生命周期 |
|---|---|---|
| .text | 程序指令、常量的一部分 | 全程 |
| .rodata | 只读常量 | 全程 |
| .data | 有初值的全局 / 静态变量 | 全程 |
| .bss | 零初始化或无显式初值的全局 / 静态变量 | 全程 |
| stack | 局部变量、返回地址、调用现场 | 随函数调用 |
| heap | malloc/new 动态分配 | 到 free/delete |

### 4.7 中断是什么

**一句话回答：**

> 中断让 CPU 暂停当前流程，先处理紧急事件，再恢复原程序，适合接收完成、定时到期、外部边沿等异步事件。

中断服务函数 ISR 的原则：

- 尽量短；
- 清中断标志；
- 只记录数据或置标志；
- 不做长延时；
- 不做阻塞等待；
- 谨慎调用不可重入函数；
- RTOS 中只调用带 FromISR 的 API。

错误示例：

~~~c
void USART_IRQHandler(void)
{
    while (1) { /* 在中断里永久阻塞，系统死掉 */ }
}
~~~

推荐结构：

~~~c
volatile bool rx_ready = false;
volatile uint8_t rx_byte;

void USART_IRQHandler(void)
{
    if (USART_RX_NOT_EMPTY()) {
        rx_byte = USART_READ_BYTE();
        rx_ready = true;
    }
}

int main(void)
{
    for (;;) {
        if (rx_ready) {
            uint8_t b;
        uint32_t irq_key = enter_critical();
        b = rx_byte;
        rx_ready = false;
        exit_critical(irq_key);  // 恢复进入临界区前的中断状态
            parse_byte(b);
        }
    }
}
~~~

## 5. STM32F407ZE 与 STM32F103C8T6

### 5.1 一句话区分

> STM32F103C8T6 是最高约 72 MHz 的 Cortex-M3 入门 MCU；STM32F407ZE 是最高 168 MHz、带 Cortex-M4F、浮点单元和更丰富外设/存储资源的高性能 MCU，适合更复杂的运动控制。

### 5.2 面试比较表

| 项目 | STM32F103C8T6 | STM32F407ZE |
|---|---|---|
| 内核 | Cortex-M3 | Cortex-M4F |
| 最高主频 | 72 MHz | 168 MHz |
| FPU | 无硬件 FPU | 单精度 FPU |
| DSP 指令 | 基础 | 更强，含 DSP 扩展 |
| 标称 Flash | C8 通常 64 KB | ZE 通常 512 KB |
| SRAM | 20 KB | 总计最高约 192 KB，具体区域特性需查手册 |
| 使用项目 | 智能台灯 | 四足机器狗 |
| 选择逻辑 | 成本低、资源足够 | 运算和外设资源更充裕 |

注意：

- 不要用网传“某些 F103C8 实际有 128 KB”代替官方规格。
- F407 的 SRAM 分多个区域，CCM RAM 与普通 SRAM 的总线可达性不同，不能只背总数。
- 具体封装引脚、外设复用、Flash/SRAM 必须以对应料号数据手册为准。

### 5.3 Cortex-M3 与 Cortex-M4F

Cortex-M4 在 M3 基础上增加了面向信号处理的指令；M4F 中的 F 表示带浮点单元。

面试说法：

> 逆运动学会用到 atan2、acos 等浮点运算。F407 的 M4F 对单精度浮点更友好，但数学库函数是否真正使用硬件 FPU，还取决于编译器浮点 ABI 和工程选项。不能只因为芯片带 FPU 就认为所有浮点都自动很快。

### 5.4 时钟树

时钟像整个系统的节拍来源：

- HSI：内部高速时钟；
- HSE：外部高速晶振；
- PLL：倍频得到更高系统时钟；
- SYSCLK：系统主时钟；
- AHB：内核、存储、DMA 等总线；
- APB1/APB2：不同外设总线；
- 外设时钟门控：不用的外设关闭以省电。

配置外设前必须开时钟，否则写寄存器可能没有效果。

定时器常见陷阱：

> 在很多 STM32F1/F4 配置中，当 APB 预分频不为 1 时，对应定时器时钟通常是 PCLK 的 2 倍。计算 PWM 前要查时钟树，不能直接把 PCLK 当 TIMxCLK。

时钟计算回答模板：

> 我先确认时钟源和 PLL 配置，得到 SYSCLK；再看 AHB、APB 分频；最后根据参考手册确认定时器是否有倍频规则，从而得到真正的 TIMx 输入时钟。

### 5.5 GPIO

GPIO 常见模式：

- 输入：浮空、上拉、下拉；
- 推挽输出：主动输出高和低，驱动能力强；
- 开漏输出：只能主动拉低，高电平靠上拉，I2C 使用；
- 模拟模式：供 ADC 等模拟外设使用；
- 复用功能：引脚交给 UART、I2C、TIM 等外设。

推挽与开漏：

> 推挽能主动拉高和拉低；开漏通常只能拉低，释放后由上拉电阻拉高。多个开漏设备可安全共享总线，所以 I2C 使用开漏结构。

### 5.6 EXTI 与 NVIC

- EXTI：检测外部引脚或内部事件的边沿；
- NVIC：管理 Cortex-M 的中断使能、优先级、嵌套。

按键或红外输入可用 EXTI，但机械按键会抖动，需要软件定时消抖或硬件 RC/施密特处理。

优先级答法：

> 抢占优先级决定一个中断能否打断另一个；子优先级常用于同一抢占级别下同时挂起时的响应顺序。数值越小通常优先级越高，但有效位数和分组要看芯片及配置。

## 6. 定时器与 PWM

### 6.1 PWM 是什么

**一句话回答：**

> PWM 通过固定周期内高电平时间所占比例，也就是占空比，控制平均能量或向设备编码目标量。

两个核心量：

- 频率：一秒重复多少次；
- 占空比：高电平时间 / 总周期。

对边沿对齐向上计数，常用近似公式：

$$
f_{PWM} = \frac{f_{TIM}}{(PSC+1)(ARR+1)}
$$

$$
Duty \approx \frac{CCR}{ARR+1}
$$

其中：

- PSC：预分频器；
- ARR：自动重装值，决定周期；
- CCR：比较值，决定高电平宽度。

### 6.2 计算例子

假设 TIM 时钟为 72 MHz，需要 1 kHz PWM：

- PSC = 71，得到 1 MHz 计数频率；
- ARR = 999，得到 1 kHz；
- CCR = 500，约 50% 占空比。

检查：

$$
72\,MHz / 72 / 1000 = 1\,kHz
$$

### 6.3 台灯调光与舵机控制不是同一种 PWM 用法

| 场景 | PWM 的意义 |
|---|---|
| LED 调光 | 高频开关改变平均电流/功率，人眼看到亮度变化 |
| 模拟舵机 | 周期脉冲中的高电平宽度编码目标角度 |

面试陷阱：

> 舵机位置主要由脉宽决定，不是简单由“占空比百分比”决定。若固定 20 ms 周期，0.5–2.5 ms 可能对应某一舵机的角度范围，但必须以具体舵机实测标定，不能统一假设。

### 6.4 为什么 LED PWM 不能太低

- 太低会肉眼闪烁；
- 摄像头下会产生条纹；
- 太高会增加开关损耗、对定时器分辨率和驱动器件提出要求。

台灯实际频率必须填写真实值，并说明选择依据。

## 7. ADC、采样与滤波

### 7.1 ADC 是什么

> ADC 把连续模拟电压量化为有限位数的数字码，STM32 常见为 12 位 ADC。

理想情况下，12 位 ADC、参考电压 3.3 V：

$$
Code \approx \frac{V_{in}}{V_{ref}} \times 4095
$$

$$
V_{in} \approx \frac{Code}{4095} \times V_{ref}
$$

如果 Code = 2048，理想电压约为 1.65 V。

注意“分辨率”不等于“绝对精度”。误差还来自：

- 参考电压误差；
- 电源噪声；
- 传感器误差；
- ADC 偏置与增益误差；
- 源阻抗过高、采样时间不足；
- PCB 布局；
- 温度漂移。

### 7.2 光敏电阻采样

光敏电阻不能直接让 ADC “测电阻”，通常与固定电阻组成分压：

~~~text
3.3 V ── 光敏电阻 ── ADC 节点 ── 固定电阻 ── GND
~~~

光越强时 ADC 是升还是降，取决于光敏电阻位于分压上臂还是下臂。

必须能回答：

- 固定电阻为什么选这个阻值；
- ADC 输入电压范围；
- 明暗阈值怎么标定；
- 如何防止临界点反复开关。

### 7.3 迟滞

如果开灯阈值和关灯阈值相同，环境光在阈值附近波动会频繁切换。

~~~c
if (!lamp_on && light_value < TURN_ON_THRESHOLD) {
    lamp_on = true;
} else if (lamp_on && light_value > TURN_OFF_THRESHOLD) {
    lamp_on = false;
}
// 例如 TURN_ON_THRESHOLD < TURN_OFF_THRESHOLD，形成迟滞区间
~~~

### 7.4 常见滤波

| 方法 | 优点 | 缺点 | 适合场景 |
|---|---|---|---|
| 均值滤波 | 简单，抑制随机噪声 | 引入延迟，怕突发异常 | 光敏、慢变化量 |
| 滑动平均 | 每次只更新一个样本 | 需要缓冲区 | 连续实时显示 |
| 中值滤波 | 对尖峰干扰有效 | 排序有开销 | 距离偶发毛刺 |
| 一阶低通 | 计算量小、平滑 | 参数影响响应速度 | 姿态、模拟量 |
| 卡尔曼滤波 | 可融合模型和噪声 | 复杂、需建模 | 不能只会调用库 |

一阶低通：

$$
y_k = \alpha y_{k-1} + (1-\alpha)x_k
$$

alpha 越大越平滑，但响应越慢。

### 7.5 采样定理与混叠

要重建最高频率为 f 的信号，理论采样频率至少大于 2f；工程中还需要留余量并加模拟抗混叠滤波。

面试不要只背“2 倍”：

> 2 倍是理想理论下限，真实系统考虑滤波器过渡带、噪声和幅相要求，采样率通常更高。

### 7.6 DMA

> DMA 能在外设和内存之间搬运数据，减少 CPU 逐字节处理的负担。

典型采集链路：

~~~text
定时器触发 ADC → ADC 转换 → DMA 循环写入缓冲区
→ 半满/全满中断 → 滤波或打包 → 显示/传输
~~~

双缓冲思想：

- CPU 处理前半区时，DMA 写后半区；
- CPU 处理后半区时，DMA 回到前半区；
- 必须保证处理速度赶得上数据产生速度。

## 8. UART / USART

### 8.1 一句话回答

> UART 是异步串行通信，双方事先约定波特率、数据位、校验位和停止位，不需要共享时钟线；USART 还可能支持同步模式，但项目里通常使用其异步功能。

### 8.2 一帧数据

常见 8N1：

~~~text
空闲高 ─ 起始位0 ─ 8个数据位 ─ 无校验 ─ 1个停止位1
~~~

8N1 含义：

- 8 个数据位；
- N：无校验；
- 1 个停止位。

UART 是全双工时通常有 TX、RX、GND 三类连接；TX 与 RX 交叉连接，双方必须共地。

### 8.3 波特率与有效吞吐

115200、8N1 时，每个有效字节通常占 10 bit，因此理论有效字节率约：

$$
115200 / 10 = 11520\ bytes/s
$$

实际还要扣除协议头、校验、空闲和处理延迟。

### 8.4 接收方案比较

| 方案 | 优点 | 风险 |
|---|---|---|
| 轮询 | 简单 | 占 CPU，可能丢数据 |
| 单字节中断 | 响应快 | 高波特率时中断频繁 |
| DMA 定长 | CPU 负担低 | 变长帧处理不方便 |
| DMA + 空闲线 | 适合变长帧 | 要正确处理缓冲区和竞态 |

### 8.5 自定义数据帧

一个可解释的帧格式：

~~~text
帧头AA 55 | 长度 | 命令 | 负载N字节 | 校验和
~~~

接收应使用状态机，而不是一看到帧头就假设后面永远正确：

~~~c
typedef enum {
    WAIT_AA,
    WAIT_55,
    WAIT_LEN,
    WAIT_BODY,
    WAIT_CHECKSUM
} ParseState;
~~~

必须处理：

- 超时；
- 长度越界；
- 校验失败；
- 帧头出现在负载中；
- 缓冲区溢出；
- 丢字节后的重新同步。

### 8.6 常见故障定位

乱码时按顺序检查：

1. 是否共地；
2. TX/RX 是否交叉；
3. 电平是 3.3 V TTL、5 V TTL 还是 RS-232；
4. 波特率和帧格式是否一致；
5. MCU 实际时钟是否正确；
6. 引脚复用是否正确；
7. 是否溢出丢字节；
8. 用逻辑分析仪解码验证。

## 9. I2C

### 9.1 一句话回答

> I2C 是使用 SCL 时钟线和 SDA 数据线的同步、地址式、半双工总线，多设备共享两根开漏线，并通过上拉电阻得到高电平。

### 9.2 核心时序

- 空闲：SCL、SDA 都为高；
- START：SCL 为高时，SDA 从高变低；
- STOP：SCL 为高时，SDA 从低变高；
- 数据一般在 SCL 高电平时稳定；
- 每 8 bit 后有第 9 个 ACK/NACK 位；
- 常见地址写成 7 位，传输时再附加 R/W 位。

读一个寄存器的常见流程：

~~~text
START
→ 从机地址 + 写
→ ACK
→ 寄存器地址
→ ACK
→ Repeated START
→ 从机地址 + 读
→ ACK
→ 读取数据
→ 主机 NACK
→ STOP
~~~

### 9.3 为什么要上拉电阻

设备只主动拉低总线，释放时靠上拉变高。这样多个设备不会出现一个强拉高、另一个强拉低的硬冲突。

上拉阻值取舍：

- 太大：上升沿慢，可能达不到高速时序；
- 太小：低电平电流大，功耗增加，设备可能拉不动。

选择与总线电容、速率、允许上升时间和设备灌电流能力有关。

### 9.4 I2C 常见故障

- 7 位地址和“左移后的 8 位地址”混淆；
- 没有上拉；
- 电平不兼容；
- 总线过长或电容过大；
- SDA 被从机一直拉低；
- ACK 未检查；
- 时钟拉伸未处理；
- 多线程同时访问未加互斥；
- 中断/超时逻辑导致总线状态机卡死。

恢复思路：

> 如果 SDA 被从机拉低，可先把 SCL 临时配置为 GPIO，发送若干时钟帮助从机退出未完成字节，再产生 STOP；具体做法要结合器件手册。

### 9.5 项目中的 I2C 设备

| 设备 | 通过 I2C 做什么 |
|---|---|
| PCA9685 | 写寄存器配置 PWM 频率和 16 路 ON/OFF 计数 |
| MPU6050 | 配置量程、采样率等并读取加速度/角速度寄存器 |
| OLED（若为 I2C） | 发送命令和显示数据 |

总线上的地址必须不冲突；速率取所有设备和布线都能支持的范围。

> SPI 通常使用 SCLK、MOSI、MISO 和每个从机的片选 CS，速度高、全双工、无统一地址和 ACK；I2C 只需两根总线、支持地址，但开漏和协议开销使其通常更慢。

## 11. 中断、轮询、DMA 的选择

| 方法 | 适合 | 不适合 |
|---|---|---|
| 轮询 | 极简单、低频、主循环空闲 | 高频数据、需低功耗 |
| 中断 | 异步事件、少量数据 | 每字节高频处理 |
| DMA | 连续大块传输、ADC/UART | 极少量偶发数据时可能过度设计 |

完整答法：

> 我先看数据频率、单次数据量、延迟要求和 CPU 负载。低频按键可轮询或 EXTI；UART 少量命令可中断；连续采样或高吞吐串口更适合 DMA。DMA 并不免除软件处理，仍要处理缓冲区边界、完成通知和溢出。

## 12. C 语言：简历写了就必须会的核心

### 12.1 从源文件到可执行文件

典型过程：

1. 预处理：展开 include、宏和条件编译；
2. 编译：把每个 C 源文件变为汇编或目标文件；
3. 汇编：生成机器码目标文件；
4. 链接：解析跨文件符号，把目标文件和库组合，按链接脚本安排地址；
5. 生成 ELF/AXF，并可转换为 BIN/HEX 下载。

常见错误：

- compile error：语法、类型等单个编译单元内的问题；
- undefined reference：声明了但链接时找不到定义；
- multiple definition：同一个外部符号被定义多次；
- hard fault：已经运行，但发生非法访问等异常。

头文件通常放：

- 类型声明；
- 函数声明；
- 宏和常量；
- 必要的 extern 声明。

不要在普通头文件直接定义一个具有外部链接的全局变量，否则多个源文件包含后可能重复定义。

~~~c
// counter.h
extern uint32_t g_counter;

// counter.c
uint32_t g_counter = 0U;
~~~

### 12.2 基本类型与固定宽度类型

嵌入式协议字段优先使用 stdint.h：

~~~c
uint8_t  command;
uint16_t adc_code;
int32_t  temperature_milli_c;
uint32_t timestamp_ms;
~~~

原因：

> C 标准只规定 char、short、int、long 的最小范围和相对关系，不保证 int 在所有平台固定为 32 位。协议、寄存器和存储布局需要明确位宽。

注意：

- char 是否有符号由实现决定；
- sizeof(char) 永远是 1，但一个字节不由标准强制等于 8 bit；在常见 STM32 工具链中是 8 bit；
- sizeof 返回 size_t，是无符号类型；
- 打印固定宽度类型时，严格写法可使用 inttypes.h 中的格式宏。

### 12.3 有符号、无符号与整数提升

经典陷阱：

~~~c
int32_t a = -1;
uint32_t b = 1U;
if (a < b) {
    // 结果未必符合直觉：比较时 a 可能转换为很大的无符号值
}
~~~

规则不用死背全部，但要养成：

- 不随意混合 signed/unsigned；
- 长度比较用 size_t；
- 算术前明确转换；
- 检查溢出；
- 位运算尽量用无符号类型。

无符号整数按模 2 的位宽回绕；有符号整数溢出是未定义行为，不能依赖。

### 12.4 指针是什么

> 指针变量保存一个对象或函数的地址，通过解引用访问对应内容。

~~~c
int value = 10;
int *p = &value;
*p = 20;              // value 变为 20
~~~

必须区分：

~~~c
const int *p1;        // 指向 const int：不能通过 p1 改值，p1 可改指向
int * const p2 = &value; // const 指针：p2 不可改指向，可改 value
const int * const p3 = &value; // 指向 const 的 const 指针
~~~

口决：

> 从变量名向外读；const 修饰它左边的内容，左边没有时修饰右边。

### 12.5 数组与指针不完全相同

数组在多数表达式中会转换为指向首元素的指针，但数组本身不是指针。

~~~c
uint8_t a[10];
sizeof(a);       // 当前作用域中为整个数组大小，通常是 10

void f(uint8_t a[10])
{
    sizeof(a);   // 形参实际调整为指针，得到指针大小，不是 10
}
~~~

二维数组传参时必须知道后续维度：

~~~c
void process(int rows[][4], size_t row_count);
~~~

### 12.6 野指针、空指针、悬空指针

- 空指针：明确不指向有效对象，C 中使用 NULL；
- 野指针：未初始化，内容不确定；
- 悬空指针：原对象生命周期已经结束，指针仍保留旧地址。

~~~c
int *bad_return(void)
{
    int local = 1;
    return &local;     // 错：函数返回后 local 生命周期结束
}
~~~

### 12.7 static、extern 与作用域

static 的两种常用含义：

1. 函数内 static 局部变量：只初始化一次，生命周期贯穿程序；
2. 文件作用域 static：符号只在当前源文件可见，形成内部链接。

~~~c
static uint32_t file_private_counter;

uint32_t call_count(void)
{
    static uint32_t count = 0U;
    return ++count;
}
~~~

extern 表示声明一个在其他地方定义、具有外部链接的符号，不负责创建第二份对象。

### 12.8 const

const 表达“程序不应通过该左值修改对象”，有利于接口约束和优化，但它不自动意味着一定放在 Flash。

~~~c
void send_bytes(const uint8_t *data, size_t len);
~~~

这个接口承诺 send_bytes 不通过 data 修改调用者的数据。

### 12.9 volatile

适用场景：

- 内存映射外设寄存器；
- 被中断异步修改并在主程序读取的简单对象；
- 某些硬件共享状态。

~~~c
volatile bool timeout_flag;
~~~

关键边界：

- 对 volatile 的 count++ 仍可能是读、加、写三步，不原子；
- 多任务共享复杂数据仍需临界区、原子操作或 RTOS 同步；
- volatile 不保证任务间的高级内存顺序。

### 12.10 struct、union、enum 与对齐

struct 把多个字段组织为一个对象：

~~~c
typedef struct {
    uint32_t timestamp_ms;
    int16_t ax;
    int16_t ay;
    int16_t az;
    uint8_t status;
} Sample;
~~~

编译器可能为了对齐插入填充，所以：

- sizeof(Sample) 可能大于字段大小之和；
- 不应直接把普通 struct 原样 memcpy 到通信线路；
- 协议应显式序列化，处理字节序和校验；
- 强制 packed 可能导致非对齐访问和性能问题。

union 让多个成员共享同一块存储。它可节省空间，但用不同成员解释对象表示涉及标准规则和可移植性，通信解析优先使用移位和 memcpy。

enum 用来表达有限状态：

~~~c
typedef enum {
    MODE_AUTO,
    MODE_MANUAL,
    MODE_BLUETOOTH,
    MODE_VOICE
} LampMode;
~~~

### 12.11 宏与 inline

错误宏：

~~~c
#define SQUARE(x) x * x
// SQUARE(a + b) 展开后优先级错误
~~~

改进：

~~~c
#define SQUARE(x) ((x) * (x))
~~~

但 SQUARE(i++) 会对 i 求值两次，仍有副作用风险。能用函数时优先：

~~~c
static inline int square_int(int x)
{
    return x * x;
}
~~~

inline 是内联建议和链接语义的一部分，不保证编译器一定展开；优化器会综合决定。

多语句宏可使用 do-while(0) 结构：

~~~c
#define SET_ERROR(code_)        \
    do {                        \
        g_error = (code_);      \
        log_error(g_error);     \
    } while (0)
~~~

### 12.12 函数指针与回调

~~~c
typedef void (*EventCallback)(uint8_t event);

static EventCallback g_callback;

void register_callback(EventCallback cb)
{
    g_callback = cb;
}

void dispatch_event(uint8_t event)
{
    if (g_callback != NULL) {
        g_callback(event);
    }
}
~~~

应用：

- 驱动完成回调；
- 状态机事件处理；
- 中断向上层通知；
- 通用设备接口。

### 12.13 栈与堆

栈：

- 自动分配和释放；
- 速度快；
- 容量有限；
- 递归、大数组、深调用可能导致栈溢出。

堆：

- malloc/new 动态申请；
- 需要手动或 RAII 管理；
- 可能碎片化、申请失败；
- 实时性和可靠性更难保证。

小型 MCU 常在初始化阶段静态分配，运行期避免频繁 malloc/free。不是“嵌入式绝对不能用堆”，而是要评估最坏时间、碎片、失败处理和生命周期。

### 12.14 常见未定义行为

- 有符号整数溢出；
- 数组越界；
- 解引用空、野或悬空指针；
- 对同一对象进行无序的多次修改；
- 移位位数大于等于类型宽度；
- 负数左移等不满足标准条件的移位；
- 使用未初始化自动变量；
- 格式化字符串与参数类型不匹配；
- 返回局部变量地址；
- 数据竞争。

面试回答：

> 未定义行为不是“一定崩溃”，而是 C 标准不规定结果，编译器可据此优化，所以调试时可能时好时坏。

### 12.15 环形缓冲区

UART 连续接收常用环形缓冲区，把“中断快速收字节”和“主循环解析协议”解耦。

~~~c
#include <stdbool.h>
#include <stdint.h>

#define RX_CAPACITY 128U

typedef struct {
    uint8_t data[RX_CAPACITY];
    volatile uint16_t head;
    volatile uint16_t tail;
} RingBuffer;

static bool ring_push(RingBuffer *rb, uint8_t byte)
{
    uint16_t next = (uint16_t)((rb->head + 1U) % RX_CAPACITY);
    if (next == rb->tail) {
        return false;                 // 满
    }
    rb->data[rb->head] = byte;
    rb->head = next;
    return true;
}

static bool ring_pop(RingBuffer *rb, uint8_t *byte)
{
    if (rb->tail == rb->head) {
        return false;                 // 空
    }
    *byte = rb->data[rb->tail];
    rb->tail = (uint16_t)((rb->tail + 1U) % RX_CAPACITY);
    return true;
}
~~~

追问：

- 为什么浪费一个槽位？为了用 head == tail 表示空，用 next == tail 表示满。
- volatile 是否足够？单生产者单消费者且索引访问原子时可能成立，但要结合平台、执行上下文和内存模型；多任务/多核不能想当然。
- 缓冲区满怎么办？丢新数据、覆盖旧数据、流控或报警，要按业务定义。

### 12.16 C 快问快答

1. **sizeof 是函数吗？**  
   不是普通函数，是运算符；多数情况下编译期求值，变长数组例外。

2. **memcpy 和 memmove 区别？**  
   memcpy 要求源与目标不重叠；重叠时用 memmove。

3. **strcmp 返回什么？**  
   小于、等于或大于 0，不保证只返回 -1、0、1。

4. **为什么不能用 == 比较浮点相等？**  
   计算存在舍入误差，通常按允许误差比较；但某些精确编码值场景需具体分析。

5. **局部 static 放栈吗？**  
   通常不放栈，具有静态存储期，常位于 .data 或 .bss。

6. **声明和定义区别？**  
   声明告诉编译器名称与类型；定义还创建实体或提供函数体。一个声明也可能同时是定义。

7. **数组名能自增吗？**  
   数组名不是可修改指针对象，不能 a++；可让独立指针 p 指向数组后 p++。

8. **指针加 1 加多少字节？**  
   移到下一个所指类型对象，地址增加 sizeof(*p)。

9. **函数参数如何返回多个结果？**  
   可通过输出指针、返回 struct，或拆分接口。

10. **如何避免缓冲区溢出？**  
    传入容量、检查长度、使用 size_t、保证字符串终止、验证外部长度字段。

## 13. C++：简历写了 C++ 时的最低知识线

### 13.1 C 与 C++ 的关系

> C++ 不是“带类的 C”这么简单，它有更强的类型系统、对象生命周期、模板和标准库。嵌入式可使用 C++ 的零成本抽象，但要谨慎评估动态内存、异常、RTTI、虚函数和库实现的资源开销。

不要说“C++ 完全兼容 C”；两者是不同语言，存在不兼容语法和语义。

### 13.2 引用与指针

~~~cpp
void set_value(int& value) { value = 10; }     // 引用
void set_value2(int* value) { if (value) *value = 10; } // 指针
~~~

一般区别：

- 引用在正常用法中必须绑定到对象，语法像对象；
- 指针可为空、可改指向、可做指针运算；
- 底层实现可能相似，但语义不同。

### 13.3 类、构造、析构

~~~cpp
class Led {
public:
    explicit Led(uint16_t pin) : pin_(pin) {
        gpio_init(pin_);
    }

    void on()  { gpio_write(pin_, true); }
    void off() { gpio_write(pin_, false); }

private:
    uint16_t pin_;
};
~~~

构造函数建立有效对象状态；析构函数在对象生命周期结束时释放资源。

### 13.4 RAII

> RAII 把资源的获取绑定到对象构造，把释放绑定到析构，让所有退出路径都自动清理。

~~~cpp
class CriticalSection {
public:
    CriticalSection()  { disable_irq(); }
    ~CriticalSection() { enable_irq(); }
    CriticalSection(const CriticalSection&) = delete;
    CriticalSection& operator=(const CriticalSection&) = delete;
};

void update_shared()
{
    CriticalSection lock;
    // 修改共享数据；即使中途 return，析构也会恢复中断
}
~~~

真实项目使用前要考虑嵌套临界区，不能用简单 disable/enable 破坏原先的中断状态。

### 13.5 继承与多态

~~~cpp
class Sensor {
public:
    virtual ~Sensor() = default;
    virtual bool read(float& value) = 0;
};
~~~

运行时多态通常通过虚函数表实现，会带来少量存储和间接调用开销。小型项目也可用模板、函数指针或组合，不能为了“面向对象”滥用继承。

### 13.6 智能指针

- unique_ptr：独占所有权；
- shared_ptr：共享引用计数所有权；
- weak_ptr：观察 shared_ptr 管理的对象，避免某些循环引用。

在无堆或严格实时 MCU 中，智能指针未必适合；如果对象静态创建，就不需要为了使用而使用。

### 13.7 STL

至少理解：

- array：固定大小数组；
- vector：动态连续数组，扩容可能重新分配；
- string：动态字符串，具体实现可能有小字符串优化；
- queue/deque：队列；
- algorithm：sort、find 等。

实时路径中使用 vector 时要预留容量或改用固定容器，避免不可预测的动态分配。

### 13.8 C++ 快问快答

1. **new/delete 与 malloc/free 区别？**  
   new/delete 处理对象构造析构并有类型；malloc/free 只分配释放原始字节。不能交叉配对。

2. **override 有什么用？**  
   显式要求函数覆盖基类虚函数，签名不匹配时编译器报错。

3. **虚析构为什么重要？**  
   通过基类指针删除派生对象时，基类析构需为虚函数，才能完整析构派生部分。

4. **拷贝和移动区别？**  
   拷贝复制资源；移动转移可转移资源的所有权，减少昂贵复制。

5. **const 成员函数？**  
   承诺不通过 this 修改普通成员，可被 const 对象调用。

## 14. FreeRTOS

### 14.1 一句话回答

> FreeRTOS 是面向微控制器的实时操作系统内核，用优先级调度多个任务，并提供队列、信号量、互斥锁、事件组和软件定时器等机制。

“实时”不等于“运行得快”，而是对响应时间有可分析、可约束的要求。

### 14.2 任务与调度

任务常见状态：

- Running：正在运行；
- Ready：可以运行，等待 CPU；
- Blocked：等待时间或事件；
- Suspended：被显式挂起。

高优先级任务就绪时可抢占低优先级任务。高优先级任务若永不阻塞，会饿死低优先级任务。

错误：

~~~c
for (;;) {
    poll_everything();  // 无延时、无阻塞的高优先级任务
}
~~~

更合理：

~~~c
for (;;) {
    sample_sensors();
    vTaskDelayUntil(&last_wake, pdMS_TO_TICKS(10));
}
~~~

vTaskDelay 是从调用时开始延时；vTaskDelayUntil 更适合固定周期任务，可减少周期漂移。

### 14.3 队列、信号量、互斥锁

| 机制 | 用途 |
|---|---|
| Queue | 复制数据或指针，在任务/中断间传消息 |
| Binary Semaphore | 事件通知、资源计数为 0/1 |
| Counting Semaphore | 多个同类资源或事件计数 |
| Mutex | 保护共享资源，通常带优先级继承 |
| Event Group | 等待多个标志位组合 |
| Task Notification | 轻量的一对一任务通知 |

互斥锁与二值信号量都可能呈现“拿/还”，但语义不同。保护资源时优先考虑 mutex，因为其所有权和优先级继承更符合场景。

### 14.4 优先级反转

场景：

1. 低优先级任务持有锁；
2. 高优先级任务等待该锁；
3. 中优先级任务持续抢占低优先级任务；
4. 高优先级任务间接被中优先级任务拖延。

优先级继承会临时提高持锁任务优先级，使其尽快释放锁，但不能替代合理的锁范围设计。

### 14.5 中断中使用 RTOS API

- 使用名称带 FromISR 的版本；
- 中断优先级必须满足 FreeRTOS 端口限制；
- 必要时请求中断退出后立即切换到被唤醒的高优先级任务；
- 不在 ISR 阻塞。

### 14.6 机器狗的任务划分示例

仅为设计示例，不代表你项目确实如此：

~~~text
通信接收任务 → 命令队列 → 运动控制任务 → 舵机目标
IMU 任务      → 姿态队列 → 安全状态机
灯效任务      ← 系统状态事件
~~~

面试时必须先说真实实现。若项目是裸机：

> 我的机器狗实际采用裸机主循环和定时器节拍，没有在该项目中使用 FreeRTOS。FreeRTOS 是我在练习项目中接触的，我理解任务、队列和互斥等基础机制。

这比把没用过的 RTOS 硬塞进项目更可信。

### 14.7 FreeRTOS 高频题

1. **任务栈太小会怎样？**  
   可能破坏邻近内存、HardFault 或出现随机错误；可启用栈溢出检查并查看高水位。

2. **队列传值还是传地址？**  
   队列复制固定大小元素；大对象常传指针，但必须管理被指对象生命周期。

3. **死锁四个条件？**  
   互斥、占有并等待、不可剥夺、循环等待。常通过固定加锁顺序、缩小锁范围、超时避免。

4. **软件定时器回调能阻塞吗？**  
   通常不应长时间阻塞，因为多个软件定时器共享定时器服务任务。

5. **任务越多越好吗？**  
   不是。任务增加会消耗栈和调度资源，也增加同步复杂度，应按并发需求划分。

## 15. MQTT 与 EMQX

### 15.1 一句话回答

> MQTT 是基于发布/订阅模型的轻量消息协议；客户端向主题发布或订阅消息，EMQX 是负责接收、路由和管理这些消息的 MQTT Broker。

角色：

- Publisher：发布者；
- Subscriber：订阅者；
- Broker：消息代理；
- Topic：分层主题，例如 dog/001/status。

### 15.2 一个完整例子

~~~text
机器狗发布：dog/001/status
负载：{"battery_mv": 7400, "state": "stand"}

网页下发：dog/001/cmd
负载：{"action": "forward", "speed": 2}
~~~

完整链路：

~~~text
STM32 ↔ UART ↔ ESP32 ↔ Wi-Fi/TCP ↔ EMQX
                                      ↕
                                  网页或后台
~~~

这只是常见架构。你的项目如果不是这样，必须按真实链路改写。

### 15.3 QoS

| QoS | 语义 | 代价 |
|---|---|---|
| 0 | 最多一次，可能丢 | 最低 |
| 1 | 至少一次，可能重复 | 中等 |
| 2 | 恰好一次的协议交付流程 | 最高 |

应用层即使用 QoS 1，也应考虑幂等。例如“设为站立”可重复执行；“前进一步”重复执行可能造成额外动作，需要消息 ID 去重。

### 15.4 Retained、Will、Keep Alive

- Retained message：Broker 保留某主题的最后一条保留消息，新订阅者可立即收到；
- Last Will：客户端异常断开时由 Broker 发布预先设置的遗嘱消息；
- Keep Alive：客户端定期保持连接活性，帮助检测失联；
- Clean Start / Session：决定会话状态如何建立和恢复，具体语义看 MQTT 版本。

### 15.5 安全

生产环境至少考虑：

- TLS；
- 每设备独立凭据；
- 主题 ACL；
- 禁止匿名访问；
- 凭据安全存储；
- 固件升级和证书轮换；
- 防止重放和越权命令。

只会在本机启动 EMQX，不等于掌握 MQTT 安全。

## 16. ESP32、Wi-Fi 与蓝牙

### 16.1 ESP32 在项目里的角色

ESP32 集成 MCU、2.4 GHz Wi-Fi 和蓝牙能力，常作为：

- 无线通信协处理器；
- 主控；
- 网关；
- 语音前端或联网节点。

必须说明机器狗中 STM32 与 ESP32 的分工：

> STM32 负责 [真实的实时运动控制]，ESP32 负责 [真实的语音/联网功能]，两者通过 UART4 交换 [真实帧格式]。这样把实时控制与较复杂的网络/语音处理分开。

### 16.2 Wi-Fi 基础

- STA：设备连接路由器；
- AP：设备自己提供热点；
- DHCP：自动获取 IP；
- DNS：域名解析为 IP；
- TCP：可靠字节流，有连接、重传和顺序；
- UDP：数据报，无连接、开销低但不保证到达与顺序。

MQTT 通常运行在 TCP 之上，也可使用 TLS 加密。网页常使用 HTTP/HTTPS 或 WebSocket。

### 16.3 经典蓝牙与 BLE

| 项目 | 经典蓝牙 | BLE |
|---|---|---|
| 常见模型 | SPP 串口等 | GAP + GATT |
| 数据组织 | 类似串行数据流 | Service / Characteristic |
| 功耗 | 通常较高 | 面向低功耗 |
| 浏览器 Web Bluetooth | 通常不是经典 SPP | 常见实现面向 BLE GATT |

简历中的“蓝牙支持网页遥控”必须查清：

- 如果用 Web Bluetooth：说明浏览器通过 BLE GATT 写入特征值；
- 如果用 HC-05 一类经典串口模块：普通网页通常不能直接当作串口访问，可能实际是 App、桌面工具或其他桥接；
- 如果网页连接 ESP32 的 HTTP/WebSocket：那本质上是 Wi-Fi 网页控制，不应称为蓝牙网页控制。

### 16.4 语音控制的三种可能架构

1. ESP32 本地离线命令词识别；
2. 外部语音识别模块识别后经 UART 给 ESP32/STM32；
3. 录音上传云端识别，再下发命令。

你必须能回答：

- 麦克风和语音模块型号；
- 识别在哪里执行；
- 支持哪些命令词；
- 误识别如何处理；
- 断网是否可用；
- UART 命令格式；
- 安全动作优先级。

不知道实际架构时，不要说“ESP32 实现语音识别”，可说“ESP32 接收语音模块输出并转发控制命令”。

## 17. PCA9685、PWM 与舵机

### 17.1 PCA9685 是什么

> PCA9685 是 NXP 的 16 通道、12 位 PWM 控制器，通过 I2C 配置每路 PWM 的开启和关闭计数点，能减少 STM32 自身 PWM 通道占用。

“12 位”表示一个周期分为 4096 个计数位置，不等于舵机真的有 4096 个可重复机械角度。

### 17.2 PWM 频率设置

按数据手册给出的基本关系，预分频值近似为：

$$
PRE\_SCALE \approx round\left(\frac{f_{osc}}{4096 \times f_{PWM}}\right)-1
$$

若内部振荡器按 25 MHz 估算，目标约 50 Hz：

$$
25\,000\,000 /(4096 \times 50)-1 \approx 121
$$

注意：

- 内部振荡器存在偏差；
- 真实板卡频率可用示波器测量并校准；
- 修改 PRE_SCALE 前通常要按手册进入 Sleep，再恢复并等待振荡器稳定；
- 不能只写寄存器却不核对输出波形。

### 17.3 舵机脉宽转计数值

如果周期 20 ms，12 位总计数 4096：

$$
count = pulse\_us \times 4096 / 20000
$$

示例：

| 脉宽 | 近似计数 |
|---:|---:|
| 1000 μs | 205 |
| 1500 μs | 307 |
| 2000 μs | 410 |

这些只是计算示例。不同舵机的安全脉宽、机械零位、方向和有效角度不同，必须逐个标定。

### 17.4 角度映射

~~~c
static uint16_t clamp_u16(uint16_t x, uint16_t lo, uint16_t hi)
{
    if (x < lo) return lo;
    if (x > hi) return hi;
    return x;
}

uint16_t servo_angle_to_count(float degree,
                              float min_degree,
                              float max_degree,
                              uint16_t min_count,
                              uint16_t max_count)
{
    if (degree < min_degree) degree = min_degree;
    if (degree > max_degree) degree = max_degree;

    float ratio = (degree - min_degree) / (max_degree - min_degree);
    float count = min_count + ratio * (float)(max_count - min_count);
    return clamp_u16((uint16_t)(count + 0.5f), min_count, max_count);
}
~~~

真实系统还需每关节保存：

- 零位偏置；
- 正反方向；
- 安全最小/最大角度；
- 安装误差修正；
- 断电或失控安全姿态。

### 17.5 舵机供电

这是机器狗高频追问。

必须回答：

- 8 个舵机不能由 STM32 3.3 V 引脚供电；
- 电源要按同时动作和堵转电流留余量；
- 舵机电源与逻辑电源要正确共地；
- 电源入口要有足够的储能和去耦；
- 大电流回路避免穿过 MCU 敏感地；
- 低电压跌落会导致舵机抖动、MCU 复位或通信异常；
- 必要时做过流、欠压和保险保护。

如果不知道舵机堵转电流，不能声称电源设计“完全足够”。应查具体型号数据手册并实测动态压降。

### 17.6 PCA9685 常见面试题

1. **为什么不用 STM32 自己的 8 路 PWM？**  
   可以使用，但需要占用多个定时器通道和引脚。PCA9685 用一条 I2C 总线扩展 16 路独立 PWM，布线和扩展更方便；代价是额外器件、I2C 更新延迟和振荡器误差。

2. **PCA9685 是专用舵机驱动器吗？**  
   它本质是 16 路 12 位 PWM LED 控制器，常被用于产生舵机控制脉冲；它不直接给舵机电机提供功率。

3. **同时更新多路会不会姿态撕裂？**  
   如果逐通道更新，通道生效时间有差异。可利用自动递增批量写、合理安排控制周期，并评估芯片寄存器更新行为。

4. **I2C 400 kHz 更新 8 路够不够？**  
   要按每次传输的字节数、协议开销和控制周期计算，不能只回答“够”。对于 20 ms 左右舵机周期，常见批量更新通常可行，但应给出自己的真实包长和实测时间。

## 18. MPU6050 与姿态

### 18.1 它直接测量什么

MPU6050 包含：

- 三轴加速度计；
- 三轴陀螺仪；
- 温度传感器；
- 数字运动处理相关能力，具体使用方式看器件资料和驱动。

它不直接“测绝对位置”，也不能只靠六轴 IMU 长时间得到无漂移的航向角。

### 18.2 常见配置知识

- I2C 地址通常由 AD0 决定为 0x68 或 0x69；
- 上电后要检查 WHO_AM_I；
- 退出睡眠；
- 配置陀螺仪和加速度量程；
- 配置数字低通和采样分频；
- 连续读取高低字并组合成有符号 16 位数据。

常见满量程选项：

- 加速度：±2 g、±4 g、±8 g、±16 g；
- 陀螺仪：±250、±500、±1000、±2000 °/s。

若配置为 ±2 g，常见灵敏度为 16384 LSB/g；若陀螺仪为 ±250 °/s，常见灵敏度为 131 LSB/(°/s)。面试时必须先说明配置，不能把数值当成所有量程通用。

### 18.3 组合高低字

~~~c
static int16_t be16_to_i16(uint8_t high, uint8_t low)
{
    uint16_t u = ((uint16_t)high << 8) | (uint16_t)low;
    return (int16_t)u;
}
~~~

注意：

- 寄存器数据高字节在前；
- C 的整数提升和强制转换要清楚；
- 连续突发读取能减少不同轴采样时刻不一致。

### 18.4 零偏校准

静止、姿态已知时采集多组数据求平均：

~~~text
gyro_corrected = gyro_raw - gyro_bias
accel_corrected = accel_raw - accel_bias
~~~

加速度计竖直轴在静止时应包含约 1 g 重力，不能把三个轴都盲目校准为 0。

温度变化会影响偏置，简单开机校准不是所有工况下的永久解决方案。

### 18.5 加速度倾角

静止或低动态时，可由重力方向估算倾角。例如一种坐标约定下：

$$
roll_{acc} = atan2(a_y, a_z)
$$

$$
pitch_{acc} = atan2(-a_x, \sqrt{a_y^2+a_z^2})
$$

公式必须与传感器安装方向和坐标系一致。

机器狗剧烈运动时，加速度计还测到线性加速度，此时它不只代表重力，倾角会受干扰。

### 18.6 陀螺积分

$$
angle_k = angle_{k-1} + gyro\_rate \times \Delta t
$$

优点：短时间响应快。  
缺点：零偏被持续积分，长期漂移。

### 18.7 互补滤波

~~~text
angle = α × (angle_previous + gyro_rate × dt)
      + (1 - α) × accel_angle
~~~

意义：

- 陀螺仪负责短期快速变化；
- 加速度计提供长期重力参考；
- alpha 不是随便抄一个 0.98，要与采样周期和期望截止频率匹配并实测。

### 18.8 倾倒检测

不能只用单次阈值：

~~~c
if (fabsf(roll) > ROLL_LIMIT || fabsf(pitch) > PITCH_LIMIT) {
    if (++over_limit_count >= REQUIRED_COUNT) {
        state = STATE_FALLEN;
    }
} else {
    over_limit_count = 0U;
}
~~~

还需考虑：

- 阈值；
- 持续时间；
- 运动时误判；
- 上电姿态；
- 传感器通信失败；
- 触发后舵机采取什么安全动作。

### 18.9 MPU6050 高频题

1. **六轴是哪六轴？**  
   三轴加速度和三轴角速度，不是六个姿态角。

2. **为什么只有六轴难以稳定求航向角？**  
   加速度能参考重力但不能提供绝对航向；Z 轴陀螺积分会漂移，通常需要磁力计或外部参考校正。

3. **采样率越高越好吗？**  
   不是。更高会增加总线、CPU 和噪声处理负担，需结合动态带宽和滤波。

4. **I2C 读不到怎么办？**  
   查供电、共地、地址、上拉、WHO_AM_I、时钟、逻辑分析仪 ACK、总线是否被拉死。

## 19. WS2812

### 19.1 一句话回答

> WS2812 类智能 RGB LED 把控制芯片与 LED 集成，每颗接收串行时序数据、取走自己的颜色字节并把剩余数据转发给下一颗。

常见特征：

- 单数据线级联；
- 常见数据速率约 800 kbit/s；
- 每颗常用 24 bit，常见顺序为 G、R、B；
- 0/1 由高低电平持续时间区别；
- 一段低电平复位 / 锁存。

具体时序容差必须以你实际器件版本数据手册为准。

### 19.2 为什么不推荐随便 bit-bang

中断打断可能破坏亚微秒级波形。常见实现：

- 关闭中断后精确翻转，但影响系统实时性；
- 定时器 PWM + DMA，稳定输出一串预先编码的占空比；
- SPI 特殊编码，把每个逻辑位扩展成多个 SPI 位。

### 19.3 电气问题

- 多颗全白时电流大；
- 数据电平阈值与 3.3 V MCU 兼容性要核对；
- 电源入口加电容；
- 数据线串联小电阻可抑制振铃；
- MCU 与 LED 共地；
- 上电顺序和长线干扰要考虑。

项目中若只有状态灯，应说清每种颜色对应什么状态，而不是只说“灯效炫酷”。

### 20.3 二连杆逆运动学

设：

- 大腿长度 L1；
- 小腿长度 L2；
- 髋关节为原点；
- 足端目标为 (x, y)；
- 关节角为 theta1、theta2。

距离：

$$
r^2 = x^2 + y^2
$$

可达条件：

$$
|L_1-L_2| \le r \le L_1+L_2
$$

膝关节角的一种定义：

$$
\cos\theta_2 =
\frac{x^2+y^2-L_1^2-L_2^2}{2L_1L_2}
$$

$$
\theta_2 = acos(clamp(\cos\theta_2, -1, 1))
$$

髋关节角：

$$
\theta_1 =
atan2(y,x) -
atan2(L_2\sin\theta_2,\ L_1+L_2\cos\theta_2)
$$

可能有“膝盖向前/向后”两支解，对应 sin(theta2) 正负选择。机械结构通常只允许其中一支。

### 20.4 为什么要 clamp

浮点舍入可能让理论上的 1.0 变成 1.0000001，直接 acos 会得到 NaN。

~~~c
static float clamp_f(float value, float min_value, float max_value)
{
    if (value < min_value) return min_value;
    if (value > max_value) return max_value;
    return value;
}

bool leg_inverse_kinematics(float x, float y,
                            float l1, float l2,
                            float *hip, float *knee)
{
    float r2 = x * x + y * y;
    float r = sqrtf(r2);

    if (r > l1 + l2 || r < fabsf(l1 - l2)) {
        return false;
    }

    float c2 = (r2 - l1 * l1 - l2 * l2) / (2.0f * l1 * l2);
    c2 = clamp_f(c2, -1.0f, 1.0f);

    float theta2 = acosf(c2);
    float theta1 = atan2f(y, x)
                 - atan2f(l2 * sinf(theta2),
                          l1 + l2 * cosf(theta2));

    *hip = theta1;
    *knee = theta2;
    return true;
}
~~~

### 20.5 数值例子

为方便计算，假设 L1 = L2 = 80 mm，目标点为 (80, -80) mm：

- r 约为 113.1 mm，在 0 到 160 mm 可达范围内；
- cos(theta2) = 0；
- theta2 的一种解为 90°；
- theta1 根据上述坐标约定为 -90°。

这个数学角不能直接写到舵机，下一步还要：

1. 弧度转角度；
2. 加机械零位；
3. 按安装方向取正负；
4. 限制安全角；
5. 映射为脉宽和 PCA9685 计数。

示例只帮助理解，不可当成你项目真实杆长和角度。

### 20.6 角度限幅与可达性不是一回事

- 可达性：几何上连杆能否到达；
- 关节限位：舵机和机械结构是否允许该角度；
- 自碰撞：几何可达且关节不过限，也可能撞到机身；
- 扭矩：静态几何可达，也可能因力矩过大而站不住。

完整安全检查应分层。

### 20.7 插值

最简单的固定角度步进：

~~~c
float move_toward(float current, float target, float max_step)
{
    float error = target - current;
    if (error > max_step) return current + max_step;
    if (error < -max_step) return current - max_step;
    return target;
}
~~~

缺点：

- 速度取决于调用周期；
- 不同关节距离不同，可能不同步到达；
- 速度瞬间从 0 变为固定值，仍有冲击；
- 没有明确加速度约束。

更好的思路：

- 按总时长归一化，让所有关节同时到达；
- 线性插值：q(t) = q0 + s(q1-q0)；
- 三次或 S 曲线规划，使速度和加速度更平滑；
- 固定定时节拍更新，避免主循环抖动。

### 20.8 步态的本质

步态至少涉及：

- 支撑相和摆动相；
- 每条腿的相位差；
- 足端轨迹；
- 步长、步高、周期；
- 重心和支撑多边形；
- 静态稳定或动态稳定。

如果你的项目只是预先排列的舵机动作，也应诚实说：

> 我实现的是基于预设足端轨迹和相位表的开环动作，没有做动力学建模、足端力反馈或闭环平衡。

这是合理的学生项目边界。

- 允许的转移；
- 进入动作；

### 20.11 机器狗调试顺序

1. 不接舵机，只验证 STM32 和日志；
2. 示波器检查一通道 PCA9685 频率和脉宽；
3. 单个舵机空载标定；
4. 单腿悬空调试方向和限位；
5. 四腿架空验证动作；
6. 低速度、限角度落地；
7. 逐步增加动作范围；
8. 检查电源压降和 MCU 是否复位；
9. 加入异常停机。

这体现工程安全意识。

### 20.12 机器狗压力追问

1. **为什么 F407 需要 168 MHz？F103 能不能做？**  
   不能只说“越快越好”。回答运算量、外设、内存和余量；二维逆解更新频率并不必然需要 168 MHz，F407 选择也可能来自现有板卡和资源。要承认 F103 在优化后也可能完成基础控制。

2. **acos 和 atan2 太慢怎么办？**  
   测量实际执行时间；降低规划频率、查表、近似、使用 FPU/优化数学库，或由高层低频算目标、底层高频插值。先测再优化。

3. **I2C 卡死会怎样？**  
   舵机保持最后脉冲可能危险。需要超时、错误计数、总线恢复、进入安全姿态或关闭输出。

4. **一个舵机堵转怎么办？**  
   基础系统若无电流/位置反馈很难直接识别；可加电流检测、超时、姿态异常判断和保险保护。不能声称已有检测，除非实际做过。

5. **为什么只有 2 自由度？**  
   简化结构和控制，能实现平面内足端运动；缺少侧向自由度，地形适应和横向运动能力有限。

6. **开环舵机控制有什么问题？**  
   普通舵机内部有位置闭环，但主控通常拿不到真实关节角和足端受力，因此整机层面仍缺少反馈，负载、打滑和机械误差无法完全补偿。

7. **9 种动作如何验证？**  
   给出测试条件、重复次数、失败判定和真实结果；没有记录就不要编成功率。

8. **为什么不用 MCU 定时器直接驱动？**  
   比较通道和引脚占用、同步、开发复杂度与 I2C 扩展代价。

9. **机械冲击来自哪里？**  
   目标跳变、速度/加速度不连续、机械间隙、负载变化、落足碰撞和电源问题。

10. **项目最需要升级什么？**  
    增加关节/足端反馈、时间参数化轨迹、供电监测、通信看门狗、异常保护和系统化测试。

## 21. 智能台灯涉及的传感器与器件

### 21.1 HC-SR04 超声波测距

**一句话回答：**

> MCU 给 Trig 一个触发脉冲，模块发出超声波；Echo 高电平持续时间近似等于声波往返时间，距离等于时间乘声速再除以 2。

$$
distance = \frac{time \times speed\_of\_sound}{2}
$$

室温附近常见快速换算：

$$
distance_{cm} \approx echo\_time_{\mu s}/58
$$

这只是近似，声速随温度变化。

典型流程：

1. Trig 输出至少约 10 μs 高脉冲；
2. 启动计时和超时保护；
3. Echo 上升沿记录开始计数；
4. Echo 下降沿记录结束计数；
5. 处理定时器溢出；
6. 计算距离并做有效范围判断 / 滤波。

推荐用定时器输入捕获，而不是在主循环 busy wait。

~~~c
typedef enum {
    ECHO_WAIT_RISING,
    ECHO_WAIT_FALLING
} EchoState;

volatile EchoState echo_state;
volatile uint32_t echo_start;
volatile uint32_t echo_ticks;
volatile bool echo_ready;

void input_capture_callback(uint32_t capture)
{
    if (echo_state == ECHO_WAIT_RISING) {
        echo_start = capture;
        set_capture_edge_falling();
        echo_state = ECHO_WAIT_FALLING;
    } else {
        echo_ticks = timer_delta_with_overflow(echo_start, capture);
        set_capture_edge_rising();
        echo_state = ECHO_WAIT_RISING;
        echo_ready = true;
    }
}
~~~

必须考虑：

- 无回波时 Echo 不按预期结束，需要超时；
- 太近、太远、软物体、倾斜表面会影响；
- 多次测量间留间隔，避免前一次余波；
- 多个超声波模块会串扰；
- 温度影响声速；
- 结果做中值或异常值过滤。

### 21.2 5 V Echo 风险

常见 HC-SR04 模块使用 5 V，Echo 也可能输出接近 5 V。STM32F103 的具体引脚是否 5 V 容忍必须查数据手册，而且模拟功能引脚和不同工作状态有限制。

安全设计可使用：

- 电阻分压；
- 电平转换器；
- 其他符合边沿速度要求的限压方案。

面试说法：

> 我不会只凭“STM32 有些引脚 5 V tolerant”就直接连接，而是确认具体引脚的 FT 标记、工作模式和绝对最大额定值。最稳妥是在 Echo 上做电平转换。

### 21.3 红外“在位”传感器

简历只写“红外感应”，必须先确认实际器件：

- PIR 人体红外：检测人体热辐射变化，适合有人移动，不擅长持续确认静止人体；
- 红外对管 / 反射传感器：通过发射和接收反射判断近距离物体；
- 红外测距器：输出与距离相关的模拟或数字量；
- 简单避障模块：阈值比较后输出数字电平。

如果是 PIR：

- 上电需要稳定时间；
- 检测范围和保持时间受模块参数影响；
- 静止人员可能不再触发；
- 应用上需用“最后一次触发时间 + 延时关灯”，不能把它当准确人数传感器。

### 21.4 传感器融合

台灯可将两类传感器分工：

- 红外：判断可能有人或有移动；
- 超声波：确认近距离目标；
- 光敏：判断环境明暗。

示例决策：

~~~text
环境暗 AND 检测到人 → 允许自动开灯
长时间无人 → 自动关灯
目标距离小于报警阈值 → 报警
传感器无效/超时 → 不直接使用旧数据
~~~

“融合”不等于简单写一个 AND。要说明：

- 每种数据的更新时间；
- 超时和无效值；
- 阈值和迟滞；
- 两传感器矛盾时的规则；
- 人工模式是否覆盖自动规则。

### 21.5 OLED

如果使用常见 128×64、1 bit OLED：

- 全屏缓存大小约为 128×64/8 = 1024 字节；
- 控制器可能是 SSD1306，但必须按实际型号回答；
- 接口可能是 I2C 或 SPI；
- 显示通常按页组织，不一定按单个像素线性排列。

I2C OLED 刷整屏的数据量较大。粗略估算：

> 400 kbit/s I2C 传 1024 字节，仅净数据就至少约 20.5 ms；加地址、ACK、命令和软件开销会更长。因此没必要每次主循环无条件全屏刷新。

优化：

- 内容变化再刷新；
- 只更新变化区域；
- 降低显示任务频率；
- 与传感器和控制任务解耦。

### 21.6 蓝牙 / 语音串口

USART2 和 USART3 各连接一个模块时，要准备：

- 两路波特率和帧格式；
- 模块电平；
- 接收方式：中断、DMA、空闲线；
- 命令协议；
- 同时收到矛盾命令时的优先级；
- 超时和非法命令处理。

一个简单命令协议可以是：

~~~text
AA 55 | LEN | SOURCE | COMMAND | VALUE | CHECKSUM
~~~

SOURCE 区分蓝牙、语音或本地按键，便于统一进入事件队列。

### 22.1 “自绘 PCB”必须会讲的流程

~~~text
→ 限流上电
→ 分电源域/分模块调试
~~~

只画过图、没有焊接上电，也应明确边界。

### 22.2 最小系统

STM32F103 最小系统通常要考虑：

- 各 VDD/VSS 供电与地；
- 每组电源脚附近的去耦；
- VDDA/VSSA 的模拟供电处理；
- 复位；
- BOOT0/BOOT1 启动配置；
- SWD 下载调试；
- 时钟源；
- 调试串口；
- 必要的 ESD/反接/过流保护。

具体电容、电阻和引脚连接以 ST 数据手册和硬件设计指南为准。

### 22.3 去耦电容为什么靠近芯片

MCU 开关瞬间需要高频电流。电源走线和封装有寄生电感，远处电源不能瞬间补给。小去耦电容靠近电源脚形成低阻抗局部回路，减小电源波动和高频噪声。

不要只背“每个电源脚 0.1 μF”，还要理解：

- 高频小电容靠近引脚；
- 板级需要较大储能电容；
- 回流路径短；
- 参考官方硬件指南；
- 电容容值会受直流偏压影响。

### 22.4 地与回流

“地”不是理想的 0 V 点。大电流舵机、LED 或 MOSFET 的回流若与 ADC/MCU 敏感回路共用狭窄路径，会产生地弹和噪声。

布局要点：

- 优先完整地平面；
- 高电流环路短而宽；
- 模拟采样远离高速开关节点；
- 去耦回路短；
- 晶振靠近 MCU、走线短且对称；
- SWD 和关键测试点可接触；
- 先布局再布线，不能先随便连通。

### 22.5 MOSFET 驱动 LED

MCU 引脚通常不能直接驱动大功率灯。常用 N 沟道 MOSFET 低边开关：

~~~text
电源正 ─ LED/限流或恒流驱动 ─ MOSFET Drain
MOSFET Source ─ GND
STM32 PWM ─ 栅极电阻 ─ Gate
Gate ─ 下拉电阻 ─ GND
~~~

选择要点：

- 在 3.3 V 栅压下的 Rds(on)，不是只看阈值电压；
- 电流和功耗；
- 开关损耗；
- 封装散热；
- LED 是否需要恒流；
- 感性负载才重点考虑续流路径，不能机械地给纯阻性 LED 套电机电路。

### 22.6 首次上电流程

1. 不装或隔离昂贵负载；
2. 万用表查电源与地是否短路；
3. 可调电源设置限流；
4. 先上电源模块，测各轨电压；
5. 检查 MCU 复位和时钟；
6. 连接 SWD，读芯片 ID / 下载最小程序；
7. 点亮一颗 LED 或输出调试串口；
8. 逐个接入传感器；
9. 最后接功率负载。

这套流程比“上电不冒烟就行”专业得多。

### 22.7 ERC、DRC、Gerber、BOM、CPL

- ERC：电气规则检查，检查原理图连接类型问题；
- DRC：设计规则检查，检查线宽、间距、过孔等；
- Gerber：生产各铜层、阻焊、丝印等图形文件；
- BOM：物料清单；
- CPL / Pick and Place：贴片坐标与方向。

必须说明自己实际导出和使用过哪些。

### 23.3 四模式状态机

模式和灯的状态是两个不同概念：

~~~c
typedef enum {
    MODE_AUTO,
    MODE_MANUAL,
    MODE_BLUETOOTH,
    MODE_VOICE
} ControlMode;

typedef struct {
    ControlMode mode;
    uint8_t brightness_level;
    bool person_present;
    bool near_alarm;
    bool sensor_valid;
    uint32_t last_presence_ms;
} LampState;
~~~

要定义：

- 模式由谁切换；
- 掉电后是否保存；
- 新模式进入时是否继承亮度；
- 自动安全规则能否覆盖手动命令；
- 蓝牙断开后回到什么状态；
- 语音误触发如何撤销；
- 报警是否独立于灯光模式。

### 23.4 一个可解释的自动控制伪代码

~~~c
void auto_mode_update(LampState *s,
                      uint16_t light,
                      bool pir_trigger,
                      bool distance_valid,
                      uint16_t distance_cm,
                      uint32_t now_ms)
{
    if (pir_trigger) {
        s->last_presence_ms = now_ms;
    }

    bool recently_present =
        (uint32_t)(now_ms - s->last_presence_ms) < PERSON_HOLD_MS;

    s->near_alarm =
        distance_valid && distance_cm < NEAR_DISTANCE_CM;

    if (recently_present && light < DARK_ON_THRESHOLD) {
        s->brightness_level = AUTO_LEVEL;
    } else if (!recently_present || light > BRIGHT_OFF_THRESHOLD) {
        s->brightness_level = 0U;
    }
}
~~~

这个例子体现：

- 非阻塞时间差；
- 无人保持时间；
- 距离有效位；
- 明暗迟滞；
- 状态与输出分离。

必须用你的真实阈值和逻辑替换。

### 23.5 millis 溢出

无符号时间差写法：

~~~c
if ((uint32_t)(now_ms - start_ms) >= timeout_ms) {
    // 超时
}
~~~

在无符号模运算下，只要超时时间小于计数器半范围等合理条件，这种写法能跨越计数回绕。不要直接写 now_ms > start_ms + timeout_ms，因为加法可能溢出。

### 23.6 “闭环”是否准确

“输入—处理—输出”不自动等于控制理论上的闭环。

- 如果光敏传感器测量实际灯照度，控制器根据目标照度持续调节 PWM，可称为照度反馈闭环；
- 如果只按环境光阈值开关灯，是简单反馈逻辑，但未必是连续闭环控制；
- OLED、蓝牙和语音只是交互链路，不构成反馈控制闭环。

更安全的说法：

> 完成了传感器采集、决策、执行和显示的软硬件完整链路。

### 23.8 台灯压力追问

1. **为什么选 F103，不选 51 或 ESP32？**  
   从外设数量、ADC、定时器、串口、成本、开发经验回答。不要只说“性能强”。

2. **PWM 分档为什么不连续？**  
   可能为了交互简单和避免频繁调整；若只是偷懒要承认。也可用线性/伽马映射改善视觉均匀性。

3. **为什么同样增加 10% 占空比，视觉亮度变化不均匀？**  
   人眼感知和 LED/驱动关系非线性，可做伽马或查表映射。

4. **光敏会不会测到台灯自己的光，导致振荡？**  
   会。可调整传感器位置、加迟滞、延时、滤波，或区分环境采样阶段。

5. **超声波为什么不用 delay 等 Echo？**  
   阻塞会影响显示和通信；输入捕获或中断能并行处理，并支持超时。

6. **四种模式的优先级是什么？**  
   必须给真实规则。一个常见原则是紧急安全 > 本地手动 > 明确远程命令 > 自动，但不代表你的实现。

7. **PCB 第一次上电失败怎么查？**  
   限流电源、查短路和电源轨、复位、晶振、SWD、最小程序，再逐模块。

8. **OLED 卡住会不会拖死控制？**  
   I2C 要有超时；显示是非关键功能，故障不应阻塞灯的核心控制。

9. **无人自动关灯如何避免误判静止的人？**  
   PIR 对静止人员能力有限，可延长保持、结合距离或其他传感器，并承认传感器局限。

10. **你的 PCB 最能体现什么能力？**  
    用真实例子回答器件选型、接口、电源、布局或问题修复，而不是只说“会画板”。

## 24. 实习经历：把三条空泛描述变成可验证故事

### 24.1 先说清业务

你应能画出真实链路，以下只是模板：

~~~text
物理信号
→ 传感器

→ 滤波/标定

→ 通信
→ 上位机解析
→ 实时曲线/存储
~~~

每一箭头都可能被追问：

- 信号范围和单位；
- 采样率和分辨率；
- 接口；
- 缓冲区；
- 滤波；
- 校验；
- 丢包；
- 时间戳；
- 显示刷新率；
- 数据存储。

### 24.3 “独立完成采集节点程序”回答模板

> 我的模块输入是 [传感器/上游数据]，输出是 [通信帧/处理结果]。程序分为 [驱动层、采集调度、滤波、协议、故障处理]。采样由 [定时器/中断/其他] 触发，数据通过 [ADC/I2C/SPI等] 获取，先进入 [缓冲区]，再做 [真实滤波]，最后按 [帧格式] 经 [真实接口] 发送。  
> 我独立完成的是 [真实范围]；硬件设计、核心算法或上位机中不是我完成的部分是 [真实边界]。

“独立完成”是高风险词。只要有人给过既有驱动、协议或框架，就应说清复用和新增部分。

### 24.4 滤波的回答模板

不要回答“用了滤波，让数据更稳定”。应回答：

> 原始数据的主要问题是 [高频随机噪声/工频干扰/尖峰/零偏/漂移]。我先用 [日志/频谱/重复采样] 观察，再选择 [算法]，窗口或参数为 [真实值]。选择它是因为 [信号变化速度、实时性、算力]。处理后的评价指标是 [标准差、峰峰值、延迟或现场效果；填真实结果]。

如果只是调用他人算法：

> 滤波算法由团队已有模块提供，我负责接入、参数验证和数据链路，不把算法本身说成我设计的。

### 24.5 “实时显示”回答模板

“实时”必须量化：

> 采集端每秒产生 [待填] 帧，通信线程接收后做 [解析/校验]，通过 [信号槽/消息队列/线程安全缓冲] 把数据交给 UI。界面以 [待填] Hz 刷新，而不是每来一个采样点都重绘。这样把高采样率与人眼所需显示率解耦，避免 UI 卡顿。

需要确认：

- 实际框架是 Qt、C# 还是其他；
- 接收线程和 UI 线程如何交互；
- 曲线点数是否限长或降采样；
- 断线重连；
- 包错误如何显示；
- 文件存储是否阻塞 UI。

### 24.6 一个完整 Bug 故事模板

用“现象—假设—证据—根因—修复—验证”比只说 STAR 更适合技术面。

> **现象**：现场出现 [真实现象]，触发条件是 [条件]。  
> **初步假设**：我把问题分成传感器、通信、软件解析和显示四层。  
> **证据**：先用 [工具] 检查 [信号/帧/日志]，排除了 [什么]；再发现 [关键证据]。  
> **根因**：最终是 [真实根因]。  
> **修复**：我修改了 [代码/参数/硬件]，并增加 [超时/校验/日志/边界检查]。  
> **验证**：在 [测试条件] 下连续运行 [真实时长或次数]，结果 [真实结果]。

如果没有量化记录，就说“当时没有保留完整量化数据，这是我复盘后认为需要改进的地方”，不要编数字。

### 25.1 基础语法例子

~~~python
from dataclasses import dataclass

@dataclass
class Frame:
    command: int
    payload: bytes

def checksum(data: bytes) -> int:
    return sum(data) & 0xFF

def parse_frame(raw: bytes) -> Frame:
    if len(raw) < 5:
        raise ValueError("frame too short")
    if raw[0:2] != b"\xAA\x55":
        raise ValueError("bad header")
    length = raw[2]
    if len(raw) != length + 4:
        raise ValueError("bad length")
    if checksum(raw[:-1]) != raw[-1]:
        raise ValueError("bad checksum")
    return Frame(command=raw[3], payload=raw[4:-1])
~~~

要能解释：

- list 可变，tuple 不可变；
- dict 键值映射；
- bytes 与 str 不同；
- with 管理文件等上下文；
- 异常处理；
- 模块与包；
- 虚拟环境；
- Python 有动态类型，但对象仍有类型。

### 25.2 串口测试思路

## 27. Qt：信号槽、串口与 UI 线程

### 27.1 信号槽

> 信号槽是 Qt 的对象通信机制。对象发出 signal，已连接的 slot 会被调用，能降低发送者和接收者之间的直接耦合。

~~~cpp
connect(serial, &QSerialPort::readyRead,
        this, &MainWindow::onReadyRead);
~~~

要能解释：

- signal 可连接多个 slot；
- 同线程常见直接调用语义；
- 跨线程常通过事件队列排队执行；
- 接收对象生命周期结束后连接会自动断开；
- 不要在 UI 线程做长时间阻塞 I/O。

### 27.2 串口接收不是“一次 readyRead 就是一帧”

readyRead 只表示“现在有一些字节”，可能是：

- 半帧；
- 一帧；
- 多帧粘在一起。

必须把字节追加到缓冲区，并循环提取完整帧。

~~~cpp
void MainWindow::onReadyRead()
{
    rxBuffer_.append(serial_->readAll());
    while (tryExtractOneFrame(rxBuffer_)) {
        // 每次提取一帧
    }
}
~~~

### 27.3 实时曲线

高采样率不等于高刷新率：

- 接收线程持续收数据；
- 数据缓冲或降采样；
- UI 定时器例如每 [真实值] ms 刷新；
- 限制屏幕点数；
- 文件写入放到独立任务或批量写。

必须按你实习真实框架保留；没有使用 Qt 就不要把这段套到实习。

## 28. MySQL 与 SQL

### 28.1 基础概念

- 数据库：有组织的数据集合；
- 表：行和列；
- 主键：唯一标识记录；
- 外键：表达表间引用关系；
- 索引：用额外结构换查询速度，增加存储和写入成本；
- 事务：一组操作作为逻辑整体。

### 28.2 一个传感器表

~~~sql
CREATE TABLE sensor_sample (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    device_id VARCHAR(32) NOT NULL,
    sampled_at DATETIME(3) NOT NULL,
    value DOUBLE NOT NULL,
    status TINYINT NOT NULL,
    INDEX idx_device_time (device_id, sampled_at)
);
~~~

查询某设备最近 100 条：

~~~sql
SELECT sampled_at, value, status
FROM sensor_sample
WHERE device_id = ?
ORDER BY sampled_at DESC
LIMIT 100;
~~~

问号表示参数化查询的占位思想，避免拼接用户输入造成 SQL 注入。

### 28.3 JOIN

~~~sql
SELECT d.name, s.sampled_at, s.value
FROM device AS d
JOIN sensor_sample AS s ON s.device_id = d.id
WHERE d.id = ?;
~~~

至少理解 INNER JOIN 与 LEFT JOIN：

- INNER JOIN 只保留双方匹配；
- LEFT JOIN 保留左表所有行，右表无匹配时为 NULL。

### 28.4 事务 ACID

- Atomicity：原子性；
- Consistency：一致性；
- Isolation：隔离性；
- Durability：持久性。

不要把“用了 MySQL”只理解为会 SELECT *。

## 33. 示波器与逻辑分析仪

### 33.1 区别

| 工具 | 观察内容 | 强项 |
|---|---|---|
| 示波器 | 连续电压随时间变化 | 幅值、边沿、噪声、振铃、电源纹波、模拟波形 |
| 逻辑分析仪 | 数字高/低及多通道时序 | 长时间数字捕获、协议解码、多路关系 |

同一个 I2C 问题：

- 逻辑分析仪看地址、ACK、数据字节；
- 示波器看上升沿是否太慢、电平是否越界、是否有振铃。

### 33.2 示波器基础

必须理解：

- 探头 ×1 / ×10；
- 带宽；
- 采样率；
- 时基；
- 垂直档位；
- 触发源、边沿和电平；
- AC/DC 耦合；
- 探头地线过长会引入环路和假振铃；
- 普通接地探头地夹通常与保护地相连，不能随便夹到非地高压节点。

测 PCA9685 舵机 PWM：

1. 地夹接系统地；
2. 探头接 PWM；
3. 设置上升沿触发；
4. 测周期和高电平宽度；
5. 改目标角，观察脉宽是否按映射变化；
6. 同时看舵机电源压降。

### 33.3 逻辑分析仪基础

- 采样率需高于信号变化速度并留足余量；
- 设置正确电压阈值；
- 协议解码参数要匹配；
- 解码正确不代表模拟电气质量一定正确；
- 长时间捕获注意缓存与触发条件。

### 33.4 面试实例

问题：UART 偶发乱码，你用什么工具？

> 我先用逻辑分析仪同时抓 TX/RX，按真实波特率解码，检查帧格式、丢字节和时序；若边沿或电平可疑，再用示波器看幅值、上升时间、噪声和共地。软件侧再检查溢出标志、缓冲区和时钟配置。

## 38. 测试 D：代码阅读与纠错

### D1：有符号与无符号

~~~c
int32_t a = -1;
uint32_t b = 1U;
printf("%d\n", a < b);
~~~

问题：结果为什么可能与直觉不同？如何改？

答案：

> 通常算术转换会把 a 转为无符号，-1 变成很大的值，所以比较为假。应让业务范围统一为同类有符号或无符号类型，并在确认范围后显式转换。

### D2：宏副作用

~~~c
#define MAX(a, b) ((a) > (b) ? (a) : (b))
int x = 1;
int y = MAX(x++, 3);
~~~

问题：风险是什么？

答案：

> 宏参数可能多次求值，若条件为真，x++ 可能再次执行。使用 static inline 函数或先计算无副作用的参数。

### D3：数组退化

~~~c
void clear(uint8_t data[64])
{
    memset(data, 0, sizeof(data));
}
~~~

问题：为什么错误？

答案：

> 函数形参数组调整为指针，sizeof(data) 是指针大小。应显式传入长度。

~~~c
void clear(uint8_t *data, size_t len)
{
    memset(data, 0, len);
}
~~~

### D4：中断共享数据

~~~c
uint32_t tick;

void SysTick_Handler(void)
{
    tick++;
}

int main(void)
{
    while (tick < 1000U) { }
}
~~~

问题：至少有什么风险？

答案：

> tick 被中断异步修改，至少应按平台场景使用 volatile，防止循环读取被优化；若读取/写入不是原子或多处修改，还需临界区。更好的代码避免用忙等浪费 CPU。

### D5：时间溢出

~~~c
if (now > start + timeout) {
    on_timeout();
}
~~~

问题：如何改？

答案：

~~~c
if ((uint32_t)(now - start) >= timeout) {
    on_timeout();
}
~~~

并说明超时范围的合理约束。

### D6：整数除法

~~~c
float voltage = adc_code / 4095 * 3.3f;
~~~

问题：为什么大部分值错误？

答案：

> adc_code 和 4095 若为整数会先做整数除法。改为：

~~~c
float voltage = (float)adc_code * 3.3f / 4095.0f;
~~~

### D7：缓冲区长度

~~~c
uint8_t payload[16];
uint8_t len = receive_length();
read_bytes(payload, len);
~~~

问题：如何防止溢出？

答案：

> 先验证 len <= sizeof(payload)，并定义异常帧处理；read_bytes 接口也应接收容量或在内部保证边界。

### D8：I2C 无限等待

~~~c
while (!i2c_flag_complete()) {
}
~~~

问题：现场风险和改法？

答案：

> 设备断开或总线卡死时永久阻塞。加入基于单调时钟的超时、错误码、总线恢复和上层降级。

### D9：浮点 acos

~~~c
float theta = acosf(cos_theta);
~~~

问题：几何上边界点偶发 NaN 怎么办？

答案：

> 先做可达性判断，再把浮点舍入后的 cos_theta 限制在 [-1,1]；同时检查分母和连杆长度有效。

### D10：RTOS 共享 I2C

~~~c
// 任务A和任务B可同时调用
i2c_write(...);
~~~

问题：风险和方案？

答案：

> 两个事务可能交叉破坏总线状态机。使用 mutex 串行化总线访问，或建立唯一 I2C 服务任务，由其他任务发队列请求；处理超时和优先级问题。

### 40.2 第二轮：项目深挖，约 40 分钟

#### 机器狗连续追问

面试官：

> 为什么选 PCA9685？

回答结构：

> 需求是 8 路舵机控制；PCA9685 通过 I2C 扩展 16 路 12 位 PWM，减少定时器通道和引脚占用。我配置约 [真实频率] Hz，角度经每关节标定映射为脉宽和计数。代价是 I2C 更新延迟、外部振荡器偏差和额外故障点。

面试官：

> 12 位是不是舵机有 4096 个角度？

回答：

> 不是。12 位只是把 PWM 周期分成 4096 个计数位置；舵机实际分辨率受脉宽有效范围、内部控制、死区、齿轮间隙和机械安装影响。

面试官：

> 逆运动学怎么求？

回答：

> 先用 r²=x²+y² 检查目标在 |L1-L2| 到 L1+L2 之间，再由余弦定理求膝角，通过 atan2 组合求髋角；处理两支解、acos 输入 clamp、关节限位和舵机零位映射。

面试官：

> 你说消除抖动，真的消除了吗？

回答：

> 更准确是减小由目标阶跃造成的冲击。1° 小步没有解决供电、死区和机械间隙，也没有让加速度连续。若升级，我会用固定周期的时间参数化轨迹，并同时测电源和机械误差。

面试官：

> MPU6050 给你的是什么？

回答：

> 三轴加速度和三轴角速度。我实际做了 [真实处理]；如果只基于加速度做倾倒，就不会声称实现了完整姿态融合。

#### 台灯连续追问

面试官：

> 四个模式同时给命令怎么办？

回答结构：

> 我把模式与事件分开，定义 [真实优先级]。安全报警优先处理；本地、远程与自动规则按 [真实规则] 决定。蓝牙断开或命令超时后回到 [真实状态]，避免保留过期控制。

面试官：

> 光敏阈值附近会怎样？

回答：

> 若开关共用一个阈值会反复跳变，所以设置开灯和关灯两个阈值形成迟滞，再配合滤波和最短保持时间。实际阈值通过 [真实标定方式] 得到。

面试官：

> HC-SR04 没有回波怎么办？

回答：

> 输入捕获等待必须有超时。超时后标记该次距离无效，恢复捕获边沿和状态机，不让控制主流程永久阻塞；上层不能继续使用过期距离。

面试官：

> 你自绘 PCB，电源和去耦怎么做？

回答：

> 按真实板子说明输入电源、稳压、每组 VDD 附近去耦、板级储能、地平面和高电流回路。若某项实际设计不完善，要说明问题与改进，不能照教材编到自己的板上。

#### 实习连续追问

面试官：

> 你“独立完成”的边界是什么？

回答：

> 我独立负责 [模块] 的 [设计/编码/测试]；复用了 [已有驱动/协议]；[硬件/算法/上位机] 由 [角色] 负责。我与他们通过 [接口] 联调。

面试官：

> 提升了多少效率？

回答：

> 如果有真实指标就给对比。如果没有，应回答“当时没有建立统一量化指标，我能确认的变化是 [可验证现象]；这是复盘后的不足，后续会提前定义操作耗时、刷新延迟或故障率等指标。”

## 42. “不卡顿”表达训练

### 42.1 三句法

任何技术题先用：

1. 它是什么；
2. 它在我的项目里做什么；
3. 一个关键参数或风险。

示例：

> I2C 是两线同步地址总线，使用开漏和上拉。机器狗里我用它连接 PCA9685 和 MPU6050。调试重点是地址、ACK、上拉和总线超时。

### 42.2 五段法

项目深问用：

1. 背景；
2. 输入输出；
3. 方案；
4. 难点和证据；
5. 结果与边界。

### 42.3 关键词卡，不背全文

机器狗卡片只写：

~~~text
F407 → PCA9685 → 8舵机
足端 → IK → 限位 → 标定 → 插值
MPU 原始六轴 → 校准/真实算法 → 倾倒
蓝牙真实链路 / ESP真实链路
最难Bug + 证据
~~~

看关键词重新组织，每次表达略有不同，才能防止面试官一打断就忘。

### 42.4 三级回答

同一问题准备三个长度：

- 15 秒：一句定义；
- 45 秒：定义 + 原理 + 项目；
- 2 分钟：再加计算、权衡、Bug 和边界。

面试官感兴趣再展开，不要一问一答五分钟。

### 42.5 打断训练

让同伴在以下位置打断：

- 自我介绍 20 秒；
- 正在讲公式时；
- 正在讲结果时；
- 故意质疑真实性；
- 突然切到另一项目。

恢复：

> 好的，我先回答这个追问。刚才主线说到 [锚点]，回答完我再接回。

### 42.6 禁止词替换

| 尽量不用 | 改成 |
|---|---|
| 就是、然后、反正 | 先说结论 / 分三点 |
| 应该是 | 我能确认的是 / 这项需查手册 |
| 完全消除 | 明显减小 / 在某测试条件下 |
| 精通 | 能独立完成 / 熟悉基础 |
| 什么都负责 | 我负责 A，与 B 角色通过 C 接口协作 |
| 没问题 | 通过了哪些测试 |

## 46. 一页速记

### 控制链路

~~~text
机器狗：命令 → 状态机 → 足端轨迹 → IK → 关节限位/标定
       → 插值 → PCA9685 → 舵机

台灯：传感器/串口 → 校验/滤波 → 模式状态机
     → PWM/报警/OLED

实习：传感器 → 采集 → 缓冲 → 滤波 → 帧 → 通信
     → 解析 → 显示/存储
~~~

### 五个公式

$$
f_{PWM} = f_{TIM}/((PSC+1)(ARR+1))
$$

$$
ADC = V_{in}/V_{ref}\times(2^N-1)
$$

$$
distance = echo\_time \times sound\_speed/2
$$

$$
\cos\theta_2=(x^2+y^2-L_1^2-L_2^2)/(2L_1L_2)
$$

$$
PCAcount = pulse\_time/period\times4096
$$

### 五个边界

1. MPU6050 输出六轴惯性数据，不直接输出无漂移姿态。
2. 1° 插值减小指令突变，不保证消除抖动。
3. 站立是姿态，不严格属于步态。
4. 传感器—控制—执行的完整链路，不一定是控制理论闭环。
5. 列在技能表不等于在项目里用过，必须说明证据和熟练边界。

### 五个调试词

> 现象 → 假设 → 证据 → 根因 → 验证
